# game: 監督として複数シーズンを遊ぶ最小版(スカウトと移籍の入札も人間が決める)

研究コード(`soccer_sim/`)は読み込むだけで変更しない。ゲーム側は `game/` にまとめる。

## 起動

```
uv run --python 3.13.3 python -m game.server            # http://127.0.0.1:8765/
uv run --python 3.13.3 python -m game.server --port 8791 --seed 11
```

Python標準ライブラリのみ。ブラウザで開くと遊べる。

## 遊び方

club_a の監督になる。1シーズンは42日(6週)。1週は「練習6日 → 試合日」。

1. 練習の週: 選手1人へ練習法(A/B)を助言してもよい(しなくてもよい)。助言は入力であって命令ではなく、従うか断るかは本人が決める。
2. 試合日: 先発2人を選ぶ。初期選択は副コーチの推奨(あなたの推定にだけ基づく)。
3. 結果画面: 出来事を 事実 / 観測 / 本人の理由 / 推定 の札つきで並べ、推定がどう動いたかを表示する。
4. 6節後に「季節の答え合わせ」が開き、あなたの推定と真実(真の技能・疲労・信頼・性格)、本人が述べた理由と実際の主因を比べられる。

5. 「次の季へ」で同じ世界が続く。研究の設定 `generations=retire_replace_v1`(と加齢 `aging_curve=hypothesis_v1`)をそのまま使う: 選手は1つ年を取り、規則に当てはまる選手が引退し、人数が足りないクラブには18歳の新人が入る。あなたの推定は持ち越す(古くなる)。新人は「未観察」(推定は定数0.5)から始まる。
6. 「クラブ史」に、終わった季ごとの順位・成績・優勝・引退・入団・技能の推定誤差(平均)が並ぶ。各季の答え合わせは後からも開ける。

開始年齢は研究の設定 `age_spread=5`(game-v3、未校正の仮の値)で29〜34歳にばらけ、新人も18〜23歳で入るので、引退は何季かにわたってずれて起きる。人数不足(移籍で減った場合)の補充は引退がなくても起きる。

7. 「移籍」タブ: 他クラブの全選手を、あなたの推定(1回の観測の誤差幅・観測回数・未観察日数)と公開記録だけで一覧する。練習の週の最初の日に1人を「偵察」でき(研究の規則どおり、費用と予備資金を払える間だけ)、移籍窓の前の試合日(毎季の季内14日と28日)には「申し出」を出す選手を選べる。成立の判定(資金・選手数・過去の所属)も、選手の受諾・拒否も研究側の規則で、あなたが決めるのは「誰に申し出るか」だけ。返答は 受けた / 断った / 不成立 で、断った場合は 本人の理由(粗い言葉)が付く。本当の原因(移籍の意思の点・条件の点)は季節の答え合わせにだけ出る。現所属が放出に同意しない場合は本人の弁がなく事実として表示する。

同じシードと同じ操作なら同じ展開になる(`tests/test_game_session.py`)。

## 構成

| ファイル | 役割 |
| --- | --- |
| `observation.py` | 観測境界。世界の状態から、監督が知ってよいものだけを名前を指定して取り出す(推定、観測した出来事、本人の述べた理由、公開記録) |
| `session.py` | 1シーズンの進行。人間の入力で、監督c1の先発決定と週の最初の助言だけを差し替え、研究側のステップ関数をそのまま使う |
| `reveal.py` | 季節の終わりにだけ真の値を返す |
| `server.py` | `http.server` の小さなAPIと単一ページUI配信 |
| `static/index.html` | UI(CDNなし) |

API: `GET /api/state`, `POST /api/new {seed}` または `{code}`, `POST /api/train {advice: null | {player_id, method}, scout: null | player_id}`, `POST /api/lineup {starters: [id, id], offers: [player_id, ...]}`(offers は窓の前の試合日だけ), `POST /api/next_season`(季節終了後のみ), `GET /api/reveal`(季節終了まで400), `GET /api/reveal/<季>`(終わった季)。保存は `POST /api/save|load {name}`、形式は seed + 入力列(助言・偵察・先発・入札)(`next_season` が季の区切り)。

## 守っていること

- 監督に真の技能・信頼・性格を渡さない。主検査は構造: `observation.VISIBLE_KEYS`(許可リスト)にないキーは `state()` と各ステップの出力の出口で例外になる。副検査は数値: 選手の記録の中で、その選手自身の真の値と一致する小数だけを漏れとする(他の選手との偶然の一致では誤検出しない)。`tests/test_game_leak.py` は20シード×4季で確認し、わざと漏らした場合に検出する自己検査つき。
- シード共有: 画面上部の「コード」(`<設定バージョン6桁>-<シード>`)を相手が「シード / コード」欄に入れて「最初から」を押すと同じ世界になる。設定バージョンは `GAME_CONFIG` のハッシュで、違うコードは理由つきで拒否する。
- 設定は研究の既存機能の組合せ(個性・助言反応・信念記録・中心化雑音・練習日の評価反映・未観察の探索)。研究の既定値は変えていない。
- 人間が決めるのは、先発・週の最初の助言・週の最初の日の偵察1件・移籍窓の入札先だけ。残りの枠、他クラブの運営、選手の返答、放出の同意(自クラブの選手が出ていく場合)、成立の判定は研究側の自動判断のまま。
- 偵察の可否・入札の費用は研究の関数(`decide_coach_training`・`decide_transfer_acquisition`・`resolve_transfer_offer_request`)の結果を使い、ゲーム側で再実装していない(表示用の必要額だけ式を写し、テストで研究の記録と一致を固定)。新しい画面のデータはすべて許可リストを通る。

## game-v7 の変更

- 途中で失敗した手は、記録済みの入力列から世界を作り直して元に戻す。状態と入力列は常に一致し、セーブは再生できる。
- 結果は「あなたの一手」(先発と副コーチ推奨の差・助言・偵察・申し出)と「自動」(折りたたみ)に分ける(`your_move`/`your_events`/`auto_events`)。
- 自クラブの選手が移籍を申し出て売れたら、お知らせ(`notices`)と本人の弁を出す(原因の点数は季の答え合わせ `sale_reasons` だけ)。
- 助言を聞く度合いは推定のまま言葉にし、断られた回数と直近の本人の弁(`advice_record`)を添える。
- 移籍画面に「必要額・いまの資金・不足」を出し、資金不足の入札は理由つきで押せなくする(研究の経済設定は変えていない)。

## 既知の限界

- 移籍窓は研究の設定 `transfer_window_cycle=per_season_v1`(game-v6、G4)で毎季の季内14日と28日にある。季内14日の窓は季1では資金が足りず入札が全件不成立になる(初期資金と予備資金・手数料の関係)。
- 本人の理由(受けた/断った)は、研究が記録した判断の関門(移籍の意思・条件の点)を粗い言葉にしたもの。研究側に移籍専用の「述べた理由」はなく、助言への反応の三値(従う/部分/拒否)に当たる段階もない。
- 自クラブの選手が他クラブから受ける申し出の放出同意は副コーチ(研究規則)のまま。

- 状態はメモリ上の1ゲームだけ。サーバーを止めると消える(セーブすれば再開できる)。
- 研究関数を一時的に差し替える方式のため、リクエストを直列に処理している(スレッド安全ではない)。
- 不確かさの表示は「1回の観測の誤差幅・観測回数・未観察日数」で、推定の確率分布ではない。
- 選手名はゲーム側の仮の名前(シードとID番号だけから決まる。研究側に名前はない。ID は小さく併記)。
- 1クラブの人数(2〜4人)は研究側の定数で、設定にない。選手を増やす案は見送った。
