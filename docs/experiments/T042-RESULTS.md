# T042 結果 — 練習の選択を運ぶのは期待利得、休養率は監督の評価の誤差を介して先発一致に届く(選手の状態変数別の介入分解、分析のみ)

実施: 2026-11-11。契約: [T042](../tasks/T042.md)、事前条件: [PROTOCOL](T042-PROTOCOL.md)、判断: [D057](../DECISIONS.md)。`soccer_sim/`は凍結T037 source_bundleとバイト一致(config追加なし、既定は`legacy`のまま)。T037〜T041と同じ3設定×84セル×168日で、22腕(順方向11・逆方向11)を実行(5,544実行、ゲート用の素のcentered_v1を252加えた)。実行: `uv run --python 3.13.3 python -B experiments/t042.py --out artifacts/t042/run`(約30分、8プロセス、`artifacts/t042/run-log.txt`)。全実行は1回だけ(失敗した全実行はなし)。

## 結論(平易に)

1. **練習の選択で利得を運ぶのは「期待利得」だけ。** 練習の選択が読む3つの状態のうち、期待利得`g`だけをもう一方の方式の値に差し替えると、先発一致は順方向(legacyの世界にcentered状態)で **+10.90pt [+9.62, +12.06]**(f = 1.26)、逆方向(centered_v1の世界にlegacy状態)で **+8.09pt [+6.94, +9.22]**(r = 0.93)(D = +8.68pt [+7.35, +9.95])。疲労知覚`f`(+1.43 / −1.29pt)と信頼`t`(+0.26 / +0.13pt)は利得を運ばない。登録の帰属規則の判定は **`single_variable(gain)`**(3設定とも同じ)。Shapley配分は期待利得が順方向96%・逆方向108%、疲労2%・−10%、信頼2%・2%。
2. **休養率が下がるほど先発一致が上がり、その道筋の約7割は「監督の評価の誤差」を介する。** 期待利得だけの差し替えで練習日の休養率は66.7% → 49.5%(−17.3pt)。腕の間の変動で、休養率10pt当たりの先発一致の総効果は **−5.47pt [−6.10, −4.80]**。そのうち **監督の評価の誤差`err`を介する間接効果が−3.50pt(64%)**、真の技能の広がり`gap`を介する間接効果が−0.47pt(9%)、直接が−1.50pt(27%)。媒介の判定は **`mediated(gap, err):partial`**(Σ間接/総 = 0.73 [0.67, 0.79])。休むと`gap`は小さく(10pt当たり−0.003)、`err`は大きく(+0.013)なる。技能の成長よりも、監督の評価が真の差をゆがめることの方が先発一致に効く。
3. **助言への応答の害は、練習の選択との相互作用として説明される(`practice_dependent`)。** 逆方向の応答の差し替え(`R`)は先発一致を+1.74pt **上げる**(R_response = −1.74 [−2.43, −1.06])が、練習の状態も差し替えた(`gftR`)と +0.42pt [−0.16, +0.98] で消える。相互作用 Ir_R = +2.16pt [+1.38, +2.97]。順方向では練習の状態が「centered」のとき応答の差し替えが−0.57pt [−1.05, −0.09]と小さく悪い。応答の差し替えは休養率を動かさず(−0.02pt)、助言に従う割合を1.5pt下げ、**`err`を0.0029下げる**。信頼を練習と応答の両方で差し替えても(`tR`)追加の効果はない。設定別では t030・t031 が`practice_dependent`、t032 は害自体が有意でない(`not_reproduced`)。
4. **理由コードは、変数ごとに「何が判断を変えるか」を示す。** 練習の判断の変わる割合(legacyの世界にcentered状態、`fwd_base`)は、期待利得だけで **46.2%**、疲労だけで6.0%、信頼だけで0.4%、3つ全部で40.7%、自己推定だけで0.0%(読まれない)。期待利得で変わる決定の89%が「休養→練習」で、遷移は`rest:rest_preference` → `method:pref_bonus`(A/B各約85,000件)。疲労だけの差し替えは休養を増やす方向(休養→練習は0%)で、変わる決定の44%が`rest:fatigue_recovery_need`を含む。信頼は助言が来た日の一部にしか効かない。**ただし理由コードは「最大の項」のラベルなので、判断を実際に変えた変数(期待利得)の名前は出ない**: 期待利得で判断が変わった決定の理由コードに`method:expected_gain`が含まれるのは15%にすぎず、変わる主な遷移は`rest_preference` → `pref_bonus`と表示される(事後の注記、下記)。
5. **助言への応答の判断と表明理由は信頼の差し替えだけで動く。** 応答の判断の16.0%が変わり(`fwd_base`)、監督に伝わる表明理由は`distrusts_coach` 60.6% → 55.1%、`trusts_coach` 14.3% → 15.3%、`personal` 25.1% → 29.6%(`fwd_R`)。練習の選択側の信頼(`t`)は助言項を介して0.4%の判断にしか効かない。
6. **既定をcentered_v1にする提案の推奨は、登録の規則で「推奨」。** 満たした条件: Dの区間の下限+7.35pt・最終技能の差+0.0057 [+0.0039, +0.0075]・最終信頼の差+0.0050 [+0.0041, +0.0060]・3設定ともD>0・f_gft 1.13 / r_gft 0.93・帰属`single_variable(gain)`・応答の害が`practice_dependent`・媒介が`mediated(...)`。**未達の条件なし。** 既定は変えない(提案のみ)。限界は下記: 「どの休養率が望ましいか」は測っておらず、移行は凍結成果物(T018以降の基準)の置換を伴う別taskで、t032では応答の害自体が有意でない。

### 6. 事後の観察(登録の予測・規則に含まれない。値を見た後に気づいたもの)

- **理由コードは判断を変えた変数を名指ししない。** 期待利得を差し替えたとき判断が変わった決定でも、理由は`rest_preference` → `pref_bonus`と付く(`expected_gain`を含むのは15%)。理由コードは「内訳の最大の項」のラベルで、判断の分かれ目(上下の差)を決めた変数ではない。変数別の差し替えは、どの変数が判断を変えるか(期待利得46.2%、疲労6.0%、信頼0.4%)を直接示す。選手の「理由の追跡」には、最大の項に加えて、差し替えで判断が変わる変数(反実仮想)を記録する方が、判断の理由を適切に表す。
- 状態のずれ(alt − real)は、全ての判断で同じ符号だった(平均と絶対値の平均が一致)。centered_v1の差は、少なくとも判断の瞬間の状態では、散らばりのずれより一様な水準のずれとして現れている。ただし履歴を含む状態の再構成の結果で、水準と幅の分離(`shifted_v1`)は未実施。
- 疲労だけの差し替えは順方向・逆方向のどちらでも先発一致を上げる(+1.43 / +1.29)が、休養率の動きは逆(+1.4 / −2.6pt)。実際には起こらない組(世界の方式の期待利得にもう一方の方式の疲労)を判断に読ませる限界の現れかもしれない。
- 媒介の`b_gap`の符号は設定別・方向別に不安定(t030の順方向で負)。`gap`と`err`の相関で、`gap`経由の間接効果は小さい(9%)。主な道筋は`err`経由。

## 限界・正直な注記

- 差し替えは判断の瞬間の状態だけで、状態の更新(信頼・期待利得の学習)は世界の方式のまま。altは同じ観察と行動の列を別の雑音で更新した再構成で、実走の履歴と同じでない。部分集合の差し替えは、実際には起こらない状態の組を判断に読ませる。
- centered_v1は平均だけでなく幅も半分にする(T037)ので、「alt」は両方を含む。期待利得の差し替えが運ぶのが水準か幅かは分離していない(状態のずれの記述は水準のずれを示唆するが、証明ではない)。
- 媒介は統計的な分解で因果の同定ではない。腕は休養率だけを動かさず(方法の選択・助言への従いも変わる)、`gap`・`err`・先発一致の関係は構成的(`signal` = 係数×`gap` − `err`)。休養率が`err`を動かす理由(監督のスコアのどの項が休む選手でゆがむか)は未分解。
- 理由コードは記録された内訳の最大項に研究者が付けたラベルで、選手の内面の説明ではない。「判断を変える変数」は差し替え(反実仮想)で得た別の情報。
- 区間はセルの再標本で、世界は3seedを共有し独立でないため過小の可能性がある。単一の指標(先発一致)への帰属で、ロスターは3人。3設定は`coach_belief='none'`で、応答が監督の信念を介する道は構造上ない。
- 全実行は1回だけで、登録した統計はすべて報告した。事後の観察は上の「事後の観察」のみ。実装中に登録の腕の値は見なかった(PROTOCOL末尾)。
