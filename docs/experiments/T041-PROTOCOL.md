## 設計の事実(コードを読んだだけ。結果は未確認)

選手の状態`PlayerMind`のうち観察雑音の方式を介して変わるのは4つ: **自己推定**`self_estimate`(自己観察`obs_skill`の指数平滑)、**期待利得**`expected_gains[A/B]`(実行した方法の`obs_gain`の指数平滑)、**信頼**`trust_by_coach[コーチ]`(助言に従った日に`|obs_gain − 自分の期待利得| − |obs_gain − 監督の予測|`で更新)、**疲労知覚**`perceived_fatigue`(練習日と試合日の疲労観察の最新値)。`obs_skill`・`obs_gain`(`true_gain + 雑音×0.35`)・疲労観察が方式に従う。これらを読む選手側の意思決定は次のとおりで、それ以外の場所は読まない(コードを読んだ範囲)。

- **練習の選択**(`decide_player_training`、練習日に毎日、全選手): 期待利得、疲労知覚、(助言の項と`follow`の選択に)信頼。
- **助言への応答**(`_player_advice_response` → `decide_advice_response`、提案を受けた日のみ): 最も信頼するコーチへの信頼。(自律・性格特性・出場満足度は雑音方式に依存しない。)
- **移籍**(`decide_transfer_bidding`の選手側: `decide_player_transfer_request`と`choose_player_transfer_offer`、移籍窓28日目と56日目): 自己推定、信頼(オファー先コーチ)。`decide_transfer_bidding`は監督側の決定(放出同意・獲得)も呼ぶが、それらは選手の状態を読まない。

信頼と期待利得の**更新**(学習)は状態の更新で、判断ではない。本taskは判断が読む値だけを差し替え、更新はsim本体の値のまま。`alt`の信頼・期待利得は、同じ観察の列と同じ実行した行動を、もう一方の方式の雑音で更新した値(監督の予測は記録されたもの)なので、「もう一方の方式の世界でこの選手が持つはずの信念」であり、更新規則の差の影響も含む。

## 追跡(tracker)と差し替え(view)の定義

- 各選手について、2本の状態の列を持つ: `real`(世界の方式のまま。sim本体の値と常に一致するはず)と`alt`(もう一方の方式)。要素は自己推定・期待利得A/B・信頼(4コーチ)・疲労知覚。初期値は初期ワールドの値。`season_youth_joined`で作られる新人は、生成された`PlayerMind`の値で両方を初期化する。
- 観察イベント`player_self_observation`(練習日)と`player_fatigue_observation`(試合日)、`advice_feedback`が追記されるたびに、sim本体と同じ式(クランプ・round6込み)で両方の列を更新する。`alt`の観察値は同じ真の値と同じ鍵つき一様乱数u、もう一方の方式の雑音(`observation_noise`、`observe_fatigue`の旗)で作る。`obs_gain`は`true_gain`(その日の最初の`composite_skill()`との差)から再構成する。再構成した`real`の観察値(`obs_skill`・`obs_gain`・疲労)と、`advice_feedback`の`self_prediction`・`obs_gain`・`new_trust`は、記録と**厳密に一致**しなければならない(ゲート)。期待利得の更新は助言フィードバックが期待利得の更新前の値を読むので、1日の終わりに適用する。
- 差し替え: 対象の意思決定の関数を呼ぶ間だけ、その選手の`self_estimate`・`expected_gains`・`trust_by_coach`・`perceived_fatigue`を`alt`の値に置き換え、呼出し後に必ず戻す(例外でも)。判断が差し替えの有無で変わるかを測るため、全ての腕で、該当チャネルの関数を**素の状態と`alt`の状態で2回呼ぶ**(関数は乱数・副作用なしの純関数)。差し替えるチャネルでは`alt`の結果を、そうでなければ素の結果を採用して実行に返す。2回目の呼出しは判断の記録を作らない。
- 世界の本物の状態(`real`)は常にsim本体が更新する。差し替えは決定にだけ効き、決定の記録(イベント)にはその決定が使った値が残る。

## 判断と理由コードの定義(結果を見る前に固定)

各チャネルについて「判断」と「理由コード」を定義する。理由コードは**その判断の記録された内訳の最大の正の項**(同点は名前順)で、研究者が機械的に付けるラベルであり、選手の内面の報告ではない。

- practice: 判断 = 選んだ行動(A / B / rest)。理由 = 選ばれた候補の内訳の最大の正の項: 方法なら `method:expected_gain` / `method:pref_bonus` / `method:advice_term` / `method:unsatisfied_drive`、休養なら `rest:rest_preference` / `rest:fatigue_recovery_need`、正の項がなければ `none`(計7種)。
- response: 判断 = `response`(complied / partial / refused)。理由 = 記録される`primary_reason`(6種: `trust_above_autonomy`、`trust_below_autonomy`、`self_disciplined`、`self_lax`、`irritated_by_low_playing_time`、`no_dominant_term`)。さらに監督に伝わる表明理由(`coach_advice_outcome`の`stated_reason`: trusts_coach / distrusts_coach / personal)の割合も記録する(実行された判断のみ)。
- transfer: 判断 = (移籍希望の有無、希望ありのとき選んだ移籍先クラブ)。理由 = 移籍希望スコアの最大の正の項(研究者側で式の係数を直書きして再計算する): `unsatisfied`(0.58×不満)、`bench_streak`(0.075×min(4,連続控え))、`ambition_x_self_estimate`(0.18×野心×max(0,自己推定−0.42))、正の項がなければ`none`(4種。忠誠の負の項は理由の候補にしない)。

指標(判断の件数あたりの割合、セルの再標本で区間つき):

- `flip_X`(チャネルXの判断が差し替えで変わる割合 = 素と`alt`で判断が異なる)、`reasonchg_X`(理由コードが異なる割合。判断が同じでも理由が変わる場合を含む)。
- 実行された判断の分布 `act_X_*` と、実行された理由コードの分布 `rsn_X_*`(各腕、D/F/Rの形で比較)。監督の表明理由 `stated_*`、助言に従った割合 `follow`。
- **理由の遷移**: 各チャネルで判断が変わった決定の(素の判断・理由)→(`alt`の判断・理由)の件数を、`fwd_base`(legacyの世界でcentered推定を読むと何が変わるか)と`rev_base`(centeredの世界でlegacy推定を読むと何が変わるか)について、全体252セルで合計して報告する(記述。区間なし)。

## 腕(arm)の定義

世界の方式W ∈ {legacy, centered_v1}、差し替えるチャネルの集合S。腕は12個(方向 × 6):

- 順方向(W=legacy、alt=centered_v1): `fwd_base`(S=∅)、`fwd_practice`、`fwd_response`、`fwd_transfer`、`fwd_pall`(選手側の全3種)、`fwd_both`(選手側の全3種 + T040の監督側の全4種: 先発選び・移籍・観察偵察の配分・助言)。
- 逆方向(W=centered_v1、alt=legacy): `rev_base`、`rev_practice`、`rev_response`、`rev_transfer`、`rev_pall`、`rev_both`。

各セルで12腕を同じ(設定, 世界, seed, 開始年齢)で走らせ、ゲート用にcentered_v1の追跡なしの素の実行を1回加える(計13実行/セル)。`fwd_base`・`rev_base`は追跡と判断の2回呼出し(読み取り専用)だけで差し替えなしの素の世界で、T037のlegacy・centered_v1と同じ履歴になるはず(ゲート)。`both`の腕は、T040の追跡(`experiments/t040.py`のTrackerとinstalled)を重ねて使う。

## 指標と統計(結果を見る前に固定)

- 単位は`lineup_decision`(84セル×168日÷7日×4クラブ=24,192件/腕/設定。全設定は72,576件)。**先発一致(主指標)** = 実際の先発が真の上位2人(真の技能、同点はid)と一致する割合。T037・T040と同じ定義。
- 副指標(帰属規則には使わない): セル平均の最終技能・最終満足度・最終信頼・移籍数(`t030.final_metrics`)、昇格率4種(T039と同じ定義)、監督の練習枠の選択(observe/propose/scout/rest)、上記の判断・理由の指標。
- 効果(すべて先発一致の差、pt。副指標も同じ形): **D** = `rev_base` − `fwd_base`(動的な利得。T040と同一のはず)。**F_X**(順方向、十分性) = `fwd_X` − `fwd_base`。**R_X**(逆方向、必要性) = `rev_base` − `rev_X`。X ∈ {practice, response, transfer, pall, both}。**交互作用** I_F = F_pall − (F_practice + F_response + F_transfer)、I_R = R_pall − (R_practice + R_response + R_transfer)。**監督側の上乗せ** J_F = F_both − F_pall、J_R = R_both − R_pall。**残差** = D − F_both(順方向)、D − R_both(逆方向)。
- 比(主指標のみ): f_X = F_X / D、r_X = R_X / D、i_F = I_F / D、i_R = I_R / D。
- 不確かさ: セルの再標本(bootstrap 1000回、固定seed 41)による95%区間。全腕・全統計が同じ再標本を共有し、差と比は再標本ごとに計算して区間を取る(パーセンタイル)。設定別(t030/t031/t032、各84セル)と全体(252セル)を出す。世界は3seedを共有し独立でないので区間は過小の可能性がある。
- 「有意」= 点の差の95%区間が0を含まない。

## 帰属規則(結果の前に固定。全体252セルで、この順に最初に当てはまるもの)

チャネルX ∈ {practice, response, transfer}が**担い手(carrier)** = F_Xの区間の下限>0 かつ R_Xの区間の下限>0。**主経路** = 担い手かつ f_X ≥ 0.5 かつ r_X ≥ 0.5(点推定)。

0. `no_gain`: Dの区間の下限 ≤ 0。帰属は意味を持たない。
1. `outside_player_estimates`: f_pall の区間の上限 < 0.5 かつ r_pall の区間の上限 < 0.5。利得の過半は選手の3つの意思決定が読む自己観察由来の状態の外にある。併記する閉包の旗: `closure_both`(f_both ≥ 0.5 かつ r_both ≥ 0.5(点推定): 監督側と合わせると過半が再現される = 監督側と選手側が合わせて初めて効く)、そうでなければ `closure_none`(両方を差し替えても過半は再現されない = 判断が読む値の外に残る)。
2. `single_route(X)`: 主経路がちょうど1つ。
3. `multiple_routes(X, Y, …)`: 主経路が2つ以上。
4. `distributed(X, Y, …)`: 主経路がなく、担い手が2つ以上。
5. `partial_single(X)`: 主経路がなく、担い手がちょうど1つ。
6. `only_jointly`: 担い手がなく、F_pallまたはR_pallが有意(チャネルは合わせて初めて効く)。
7. `unattributed`: 上のどれでもない。

併記する旗(分類を変えない): `interaction` = |i_F| ≥ 0.25 または |i_R| ≥ 0.25 かつ対応するI_F/I_Rの区間が0を含まない。`harm(X)` = F_XまたはR_Xの区間の上限<0(Xはpractice/response/transfer)。`coach_adds` = J_FまたはJ_Rの区間が0を含まない。設定別にも同じ規則を当てて報告する(判断規則には全体のみ使う)。

## ゲート(どれかが破れたら結果を出さずに原因を直す、または失敗として記録)

1. **sim不変**: `soccer_sim/`の全ファイルが凍結T037 source_bundleとバイト一致。
2. **素の腕は読み取り専用**: `fwd_base`がT030/T031/T032保存済みsummaryの最終値・イベント数と252/252一致。`rev_base`が追跡なしの素のcentered_v1の実行と最終値・イベント数・先発一致の件数で252/252一致。`_validate_league_invariants`が全実行(3,024)で通る。
3. **追跡の厳密性**: 全ての自己観察・疲労観察・助言フィードバックで(a)再構成した値が記録と厳密に一致、(b)毎日の終わりに全選手(引退・新人を含む)の`real`列がsim本体の`PlayerMind`と厳密に一致、(c)雑音と疲労の記録がイベントと1対1。`both`の腕ではT040の監督側の厳密性も同様。破れたら即中止。
4. **`alt`列の検証**: 1日目の終わりに、全252セル×2方向で、`alt`列が、もう一方の方式の素の世界の同日の実際の選手状態と2e-6以内で一致する(1日目の意思決定は両方式で同一なので厳密に一致するはず)。
5. **差し替え機構の恒等**: 6セル(T040と同じ選び方)で、`alt`を世界の方式自身にした全7チャネル差し替え(`both`)の腕が、素の世界とスナップショット全体(identityを除く)のsha256まで一致する(2回呼出しが副作用を持たないことの確認)。実行後の状態が追跡前と同一。
6. **T037とT040の再現**: `fwd_base`・`rev_base`の先発一致のnと平均が、設定別にT037保存値と一致(1e-9)。D = T040のD(1e-12)。
7. **凍結成果物**: 旧成果物inventory(`artifacts/t041/preflight/`)のhash不変、source_bundle保存、全unittest合格(3.13.3)。

## 予測(反証され得る。事前の信頼を併記。値は3設定合計)

事前の考え方(結果を見る前の推論): legacyの雑音は平均が−幅(技能の観察が約−0.018、疲労の観察が約−0.025)なので、legacyの選手は自己推定を低く、期待利得を(観察が`true_gain+雑音×0.35`なので約−0.006)低く、疲労知覚を低く持つ。練習の選択は期待利得と疲労知覚に直接反応するので、水準のずれを最も直接受け取る判断と考える。信頼は監督の予測と自分の期待利得の差で動くので、水準のずれの影響は間接的で、助言への応答は信頼が自律の近くにあるときだけ判断が変わりうる。移籍は窓が2回(28日・56日)しかなく小さいと考える。ただし、T040で監督側の全差し替えが約0だったことは、利得が選手側を通るか、監督側と選手側が合わせて初めて効くか(`only_jointly`の型)の両方を許す。

- **P1(機構)**: ゲート1〜7が通る。信頼約80%(選手側の追跡は新しく、助言フィードバックの再構成に未確認の点がある)。
- **P2(利得の再現)**: DがT040の+8.68ptと一致(1e-12)。決定的なので信頼95%。
- **P3(選手側が運ぶ割合)**: f_pall ≥ 0.5(順方向の選手側全3種の差し替えがDの過半を再現)。信頼約45%。
- **P4(必要性も)**: r_pall ≥ 0.5。信頼約40%。
- **P5(閉包)**: f_both ≥ 0.5 かつ r_both ≥ 0.5。信頼約65%(残りは判断が読む値の外の経路)。
- **P6(練習の選択が最大の単独チャネル)**: F_practiceが3つの単独チャネルの中で最大、かつ R_practiceも最大。信頼約55%。
- **P7(練習の選択の大きさ)**: f_practice ≥ 0.30。信頼約40%。
- **P8(移籍は小さい)**: |F_transfer| < 1.0pt かつ |R_transfer| < 1.0pt。信頼約80%。
- **P9(応答は小さい)**: |F_response| < 1.0pt かつ |R_response| < 1.0pt。信頼約55%。
- **P10(加法性)**: |i_F| ≤ 0.25 かつ |i_R| ≤ 0.25。信頼約50%。
- **P11(設定間の一貫)**: F_pallの符号が3設定とも正。信頼約55%。
- **P12(判断の変わる量)**: `fwd_base`の`flip_practice` ≥ 5%(legacyの世界でcentered推定を読むと練習の選択の5%以上が変わる)。信頼約60%。`flip_response` ≥ 5%は信頼約30%、`flip_transfer` ≥ 5%は信頼約25%。
- **P13(理由の変わり方)**: 練習の選択で判断が変わった決定のうち、変わる前後のいずれかの理由が`rest:fatigue_recovery_need`または`method:expected_gain`であるものが過半(疲労知覚と期待利得の水準が練習の選択を動かす)。信頼約65%。
- **P14(帰属の分類、全体)**: `distributed` 約15%、`single_route` 約20%、`multiple_routes` 約5%、`partial_single` 約15%、`outside_player_estimates` 約25%(うち`closure_both`が約半分)、`only_jointly` 約10%、その他10%。
- **P15(副指標)**: `fwd_pall`の最終技能の変化がcentered_v1(`rev_base`−`fwd_base`)と同じ符号。信頼約55%。

## 判断規則(結果の前に固定)

- 既定は**変えない**。推奨は提案のみ(別taskで、凍結成果物の基準の置換を伴う)。
- centered_v1を既定にする提案の推奨度(全体252セルで):
  - **推奨**: 帰属が`single_route`・`multiple_routes`・`distributed`・`partial_single`のいずれか(Dが有意で、利得が特定の選手側の意思決定の経路に帰属される)、かつ f_pall ≥ 0.5 かつ r_pall ≥ 0.5(点推定)、かつ3設定ともD>0、かつ最終技能の差(`rev_base`−`fwd_base`)と最終信頼の差の区間の下限がともに≥0、かつ`harm`の旗がない。
  - **条件つき**: Dが有意(下限>0)で最終技能の差の区間の下限≥0だが、上の「推奨」の条件のどれかを満たさない。条件は、満たさなかった項目を別taskで解消すること。
  - **保留**: 上のどちらも満たさない(Dの区間が0を含む、または最終技能が悪化)。この場合も「centered_v1が悪い」ではなく「機構が未説明」。
- 失敗条件: ゲートの破れ、追跡や差し替えによるsim結果の変化、T037保存値の1つでも不一致。予測の外れは失敗ではなく結果として記録。

## 限界(結果を見る前に記す)
