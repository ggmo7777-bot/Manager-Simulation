## 設計の事実(コードを読んだだけ。結果は未確認)

監督の各選手についての推定は技能・試合評価・疲労の3つと、方法ごとの残差(`method_residuals` A/B)。これらを読む監督側の意思決定は4つで、読む場所は次のとおり。

- **先発選び**(`decide_club_lineup`を`_step_matchday`から呼ぶ): 技能・試合評価・疲労。毎試合日(7日おき)、4クラブ。
- **移籍**(`decide_transfer_release`・`decide_transfer_acquisition`。どちらも内部で`decide_club_lineup`を呼び、獲得は候補選手の3推定も読む): 移籍窓は28日目と56日目のみ(`TRANSFER_WINDOW_DAYS`)。
- **観察・偵察の配分**(`decide_coach_training`の`observe`と`scout`の候補): 観察は技能(需要 = 0.78 − 技能)、偵察は技能(関心)。
- **助言**(`decide_coach_training`の`propose`の候補): 技能(需要)、疲労(罰)、方法の残差(予測)。選ばれた提案の予測値は選手に渡る。

練習日の各枠は4種の候補(observe・propose・scout・rest)の最大スコアで決まる。したがって配分と助言は同じ枠を競う。

観察の雑音は`legacy`が`(u−0.5)×2×幅`、`centered_v1`が`u×幅`(同じ鍵つき一様乱数u)で、`legacy = 2×centered − 幅`、`centered = (legacy + 幅)/2`(shifted_v1経由)。疲労の観察も同じuで、`observe_fatigue`の`centered`/`shifted`の旗だけが違う。観察の雑音は監督の観察(練習・試合・偵察)と、選手の自己観察(自己推定・疲労知覚・期待利得・信頼。選手側の意思決定=練習の選択・移籍希望・オファーの選択・助言への応答が読む)の両方で方式に従う。**選手側の経路は本taskの差し替えの対象外**で、残差に入る。

## 追跡(tracker)と差し替え(view)の定義

- 各(監督, 選手)について、2本の推定の列を持つ: `real`(世界の方式のまま。sim本体の値と常に一致するはず)と`alt`(もう一方の方式)。要素は技能・試合評価・疲労・残差A・残差B。初期値は初期ワールドの値、`season_youth_joined`では全監督で事前値(0.5, 0.5, 0.10, 残差0)に戻す。
- 観察イベント(`coach_session_observation`・`coach_match_observation`・`coach_scout_observation`)が追記されるたびに、sim本体と同じ式(クランプ・round6込み)で両方の列を更新する。`alt`の観察値は同じ真の値と同じu、もう一方の方式の雑音で作る: 練習・偵察は観察時点の`composite_skill()`、試合は記録された選手統計から`perf_raw`を再構成、助言の残差は日の最初の`composite_skill()`との差から`true_gain`を再構成する。再構成した`real`の観察値(雑音を含む)は記録された観察値と**厳密に一致**しなければならない(ゲート)。疲労は`observe_fatigue`を同じ引数・同じ鍵でもう一方の方式の旗で呼んだ値。
- 差し替え: 対象の意思決定の関数を呼ぶ間だけ、その監督の全選手の`skill_estimate`・`match_rating_estimate`・`fatigue_estimate`・`method_residuals`を`alt`の値に置き換え、呼出し後に必ず戻す(例外でも)。移籍は`decide_transfer_release`/`decide_transfer_acquisition`の呼出し全体を差し替える。配分と助言は、`decide_coach_training`を素の推定と`alt`で2回呼び、`observe`・`scout`の候補は配分の差し替えの有無で、`propose`の候補は助言の差し替えの有無で、どちらの呼出しの候補を使うかを決め、sim本体と同じ規則(スコア、種類の優先、対象、方法)で最大を選ぶ。`rest`は素の呼出しのもの。
- 世界の本物の推定(`real`)は常にsim本体が更新する。差し替えは決定にだけ効き、決定の記録(イベント)にはその決定が使った値が残る。

## 腕(arm)の定義

世界の方式W ∈ {legacy, centered_v1}、差し替えるチャネルの集合S ⊂ {lineup, transfer, allocation, advice}。腕は12個:

- 順方向(W=legacy、alt=centered_v1): `fwd_base`(S=∅)、`fwd_lineup`、`fwd_transfer`、`fwd_allocation`、`fwd_advice`、`fwd_all`(S=全4)。
- 逆方向(W=centered_v1、alt=legacy): `rev_base`、`rev_lineup`、`rev_transfer`、`rev_allocation`、`rev_advice`、`rev_all`。

各セルで12腕を同じ(設定, 世界, seed, 開始年齢)で走らせ、ゲート用にcentered_v1の追跡なしの素の実行を1回加える(計13実行/セル)。`fwd_base`・`rev_base`は追跡(読み取り専用)だけで差し替えなしの素の世界で、T037のlegacy・centered_v1と同じ履歴になるはず(ゲート)。

## 指標と統計(結果を見る前に固定)

- 単位は`lineup_decision`(84セル×168日÷7日×4クラブ=24,192件/腕/全設定は72,576件)。**先発一致(主指標)** = 実際の先発が真の上位2人(真の技能、同点はid)と一致する割合。T037と同じ定義。
- 副指標(登録、帰属規則には使わない): セル平均の最終技能・最終満足度・最終信頼・移籍数(`t030.final_metrics`)。昇格率4種(T039と同じ定義: `promo_played`、`promo_benched`、`promo_benched_top2`、`promo_played_not_top2`)。練習の各枠の選択の件数(observe/propose/scout/rest)と、選手あたりの観察イベント数。
- 効果(すべて先発一致の差、pt。副指標も同じ形): **D** = `rev_base` − `fwd_base`(動的な利得)。**F_X**(順方向、十分性) = `fwd_X` − `fwd_base`。**R_X**(逆方向、必要性) = `rev_base` − `rev_X`。X ∈ {lineup, transfer, allocation, advice, all}。**交互作用** I_F = F_all − Σ_{X≠all} F_X、I_R = R_all − Σ R_X。**残差** = D − F_all(順方向)、D − R_all(逆方向)。
- 比(主指標のみ): f_X = F_X / D、r_X = R_X / D、i_F = I_F / D、i_R = I_R / D。
- 不確かさ: セルの再標本(bootstrap 1000回、固定seed 40)による95%区間。全腕・全統計が同じ再標本を共有し、差と比は再標本ごとに計算して区間を取る(パーセンタイル)。設定別(t030/t031/t032、各84セル)と全体(252セル)を出す。世界は3seedを共有し独立でないので区間は過小の可能性がある。
- 「有意」= 点の差の95%区間が0を含まない。

## 帰属規則(結果の前に固定。全体252セルで、この順に最初に当てはまるもの)

チャネルXが**担い手(carrier)** = F_Xの区間の下限>0 かつ R_Xの区間の下限>0。**主経路** = 担い手かつ f_X ≥ 0.5 かつ r_X ≥ 0.5(点推定)。

0. `no_gain`: Dの区間の下限 ≤ 0。帰属は意味を持たない。
1. `outside_coach_estimates`: f_all の区間の上限 < 0.5 かつ r_all の区間の上限 < 0.5。利得の過半は監督の推定を読む4つの意思決定の外(選手側の自己観察など)にある。
2. `single_route(X)`: 主経路がちょうど1つ。
3. `distributed(X, Y, …)`: 主経路がなく、担い手が2つ以上。
4. `partial_single(X)`: 主経路がなく、担い手がちょうど1つ。
5. `only_jointly`: 担い手がなく、F_allまたはR_allが有意(チャネルは合わせて初めて効く)。
6. `unattributed`: 上のどれでもない。

併記する旗(分類を変えない): `interaction` = |i_F| ≥ 0.25 または |i_R| ≥ 0.25 かつ対応するI_F/I_Rの区間が0を含まない。`harm(X)` = F_XまたはR_Xの区間の上限<0。設定別にも同じ規則を当てて報告する(判断規則には全体のみ使う)。

## ゲート(どれかが破れたら結果を出さずに原因を直す、または失敗として記録)

1. **sim不変**: `soccer_sim/`の全ファイルが凍結T037 source_bundleとバイト一致。
2. **素の腕は読み取り専用**: `fwd_base`がT030/T031/T032保存済みsummaryの最終値・イベント数と252/252一致。`rev_base`が追跡なしの素のcentered_v1の実行と最終値・イベント数・先発一致の件数で252/252一致。`_validate_league_invariants`が全実行(3,276)で通る。
3. **追跡の厳密性**: 全観察イベントで(a)再構成した観察値(雑音込み)が記録と厳密に一致、(b)`real`列がsim本体の評価値(技能・試合評価・疲労・残差)と厳密に一致、(c)雑音と疲労の記録がイベントと1対1で対応(監督・選手・チャネル)。破れたら即中止。
4. **`alt`列の検証**: 1日目の終わりに、全252セル×2方向で、`alt`列が、もう一方の方式の素の世界の同日の実際の推定と2e-6以内で一致する(1日目の意思決定は両方式で同一なので厳密に一致するはず)。
5. **差し替え機構の恒等**: 6セル(T037のgateの選び方と同じ)で、`alt`を世界の方式自身にした(差し替えても値が変わらない)全4チャネル差し替えの腕が、素の世界とスナップショット全体(identityを除く)のsha256まで一致する。差し替えの復元の確認として、実行後の評価値が追跡前と同一。
6. **T037の再現**: `fwd_base`・`rev_base`の先発一致のnと平均が、設定別にT037保存値と一致(1e-9)。
7. **凍結成果物**: 旧成果物inventory(`artifacts/t040/preflight/`)のhash不変、source_bundle保存、全unittest合格(3.13.3)。

## 予測(反証され得る。事前の信頼を併記。値は3設定合計)

事前の考え方(結果を見る前の推論): T039では、同じ状態でオフセットを除く静的な再順位付けは負の効果で、利得は履歴が変わる経路にあった。履歴を変えるのは「誰が試合に出て観察されるか」(先発選び → 試合の観察は先発だけに入る)と「誰が練習で観察されるか」(配分 → 控えの観察の唯一の経路)。移籍は窓が2回(28日・56日)しかなく、助言は選手の練習の選択を通るため直接は先発の的確さに効きにくい。したがって、先発選びと配分が主な担い手で、移籍と助言は小さいと考える。一方、逆方向(必要性)は順方向(十分性)と異なりうる(相互作用)。

- **P1(機構)**: ゲート1〜7が通る。信頼約85%。
- **P2(利得の再現)**: D(`rev_base` − `fwd_base`)がT039の+8.68ptと一致(1e-9)。決定的なので信頼95%。
- **P3(監督の推定の意思決定が運ぶ割合)**: f_all ≥ 0.5(順方向の全4チャネル差し替えがDの過半を再現)。信頼約55%。残りは選手側の自己観察など。
- **P4(先発選びが最大の単独チャネル)**: F_lineupが4つの単独チャネルの中で最大。信頼約40%。
- **P5(先発選びの大きさ)**: f_lineup ≥ 0.30。信頼約45%。
- **P6(配分の大きさ)**: f_allocation ≥ 0.15。信頼約45%。
- **P7(移籍は小さい)**: |F_transfer| < 1.0pt かつ |R_transfer| < 1.0pt。信頼約75%(窓が2回のみ。ただし移籍で履歴が大きく分岐しうる)。
- **P8(助言は小さい)**: |F_advice| < 1.0pt かつ |R_advice| < 1.0pt。信頼約60%。
- **P9(加法性)**: |i_F| ≤ 0.25 かつ |i_R| ≤ 0.25。信頼約50%。
- **P10(順逆の対称性)**: 各単独チャネルで |f_X − r_X| ≤ 0.25。信頼約45%(十分性と必要性は相互作用でずれる)。
- **P11(設定間の一貫)**: 先発選びのF_lineupの符号が3設定とも正。信頼約55%(t030は控えの観察が少なく構造が異なる)。
- **P12(帰属の分類、全体)**: `distributed` 約35%、`single_route` 約20%、`partial_single` 約15%、`outside_coach_estimates` 約15%、`only_jointly` 約10%、その他5%。
- **P13(副指標)**: 順方向の全4チャネル差し替え(`fwd_all`)の最終技能の変化が、centered_v1(`rev_base`−`fwd_base`)と同じ符号。信頼約60%。

## 判断規則(結果の前に固定)

- 既定は**変えない**。推奨は提案のみ(別taskで、凍結成果物の基準の置換を伴う)。
- centered_v1を既定にする提案の推奨度(全体252セルで):
  - **推奨**: 帰属が`single_route`・`distributed`・`partial_single`のいずれか(Dが有意で、利得が特定の意思決定の経路に帰属される)、かつ f_all ≥ 0.5(点推定)、かつ3設定ともD>0、かつ最終技能の差(`rev_base`−`fwd_base`)と最終信頼の差の区間の下限がともに≥0(T037の指標でcenteredがlegacyに劣らない)、かつ`harm`の旗がない。
  - **条件つき**: Dが有意(下限>0)で最終技能の差の区間の下限≥0だが、上の「推奨」の条件のどれかを満たさない(帰属が`outside_coach_estimates`・`only_jointly`・`unattributed`、f_all<0.5、設定間で符号が不一致、`harm`あり)。条件は、満たさなかった項目を別taskで解消すること。
  - **保留**: 上のどちらも満たさない(Dの区間が0を含む、または最終技能が悪化)。この場合も「centered_v1が悪い」ではなく「機構が未説明」。
- 失敗条件: ゲートの破れ、追跡や差し替えによるsim結果の変化、T037保存値の1つでも不一致。予測の外れは失敗ではなく結果として記録。

## 限界(結果を見る前に記す)

- 差し替えは決定の瞬間の評価値だけで、観察の機会・選手側の経路(自己観察・信頼・助言への応答の自己推定)は世界の方式のまま。残差はその経路と相互作用を含む。centered_v1は平均だけでなくばらつきも半分にする(T037: 平均+ばらつきの分解。`shifted_v1`での差し替えは対象外)ので、本taskの「centered_v1の推定」は両方を含む。
- 「alt」は、同じ観察の列が別の雑音方式なら監督が持つはずの推定の再構成で、世界の方式を変えた実走と同じ履歴を意味しない(観察の配分が変わると、実際に観察される選手が変わる)。腕は介入の定義であって、centered_v1の世界の部分的な再現ではない。順方向と逆方向を併せて見るのはこのため。
- 単一の指標(先発一致)への帰属で、他の指標(最終技能・信頼)への帰属は副指標の記述にとどまる。ロスターは3人(先発2人、控え1人)で、世界は3seedを共有する。
