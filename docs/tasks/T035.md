# T035 — 観察雑音の中心のずれ(平均−noise)は設計か不具合か、推定誤差のどれだけを説明するか(規則を足さない分析)

2026-11-11、実装前登録(結果を見る前に方法・予測・失敗条件を固定)。状態: 実装前(未実装)。ブランチt035はorigin/main(T034まで)から積む。[事前条件](../experiments/T035-PROTOCOL.md)、判断: D050。担当: Claude Sonnet 5.5。

## 問題

T034は副次的に、simの観察雑音が`(uniform_from_key(...)−0.5)×2×noise`で作られ、`uniform_from_key`の既定範囲が[−1,1]のため、雑音が[−3,+1]×noise(平均−noise)になることを見つけた(未検証)。全ての監督の推定が系統的に低く出るなら、新人の遅れの切り分け(T034)や以後の全ての比較に効くので、観察の頻度の規則(初見の観察の加点)を考える前に、まずこのずれの大きさ・設計意図の有無・推定誤差の説明量を測る。

## 最小の選択

**シミュレーションは変えない。** (1) 全呼び出し箇所をASTで列挙し、(2) 記録済みの観察イベント(練習日・偵察・試合)から実現した雑音をキーから再計算して種類別に中心を測り、(3) 同じ雑音の引きを「中心化した版」(`u∈[−1,1]`をそのまま`u×noise`)に置き換えた場合の監督の推定の差を線形に伝播して(全選手、世界の開始から)、`lineup_decision`時点の推定誤差のうちどれだけがずれで説明されるかを新人・新人以外で測る。結果は世界へ戻さない。不具合なら**直さず**、別taskの候補として記述する。

- 新規の規則・config・イベント・worldフィールド・乱数は無い。`soccer_sim/`は1バイトも変えない。対象はT034と同じ3設定×84セル(168日)。新規コードは`experiments/t035.py`と`tests/test_t035.py`のみ。成果物は`artifacts/t035/`のみ。
