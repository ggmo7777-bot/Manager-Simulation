# T022 — リーグ保存の読込高速化(信頼manifest付き直接reader)

2026-11-10、実装前登録(結果を見る前に規則を固定)。状態: 完了(2026-11-10、成功条件1〜5を満たす)。[結果](../experiments/T022-RESULTS.md)。1000日で4.1〜5.8倍、84日で3.6〜4.4倍(読込のみ)。担当: Claude Sonnet 5.5。着手は継続指示に基づく。[事前条件](../experiments/T022-PROTOCOL.md)、判断: D037。

## 問題

`load_league_snapshot`は初期条件から全履歴を再演して全フィールドを照合する。費用は日数に比例し、Python 3.13.3の実測(seed100、open_solidarity、3回)で35日 約1.2秒、84日 約2.5秒、1000日 約14.6秒(sampledは0.5/1.2/6〜11秒、ばらつき大)。保存時の検証も同じ全再演を行う。

## 最小の選択

全再演は「ファイルが規則どおりの履歴か」の証明であり、直接復元はこの証明を外す。そこで認証読込(従来の全再演)を既定のまま残し、別名の`load_league_snapshot_trusted`を追加する。保存時に全再演で検証済みの`snapshot_sha256`(manifest.json)とファイルのdigestが一致し、identity(save17とsource hash)が現行と一致するときに限り、各状態のfrom_dictで直接復元して再直列化がsnapshotと完全一致することを確認する。

- 採らない案: (a)定期checkpointの保存(保存形式の変更とsave版上げが必要で、checkpoint自体の信頼が同じ問題を持つ)、(b)再演の最適化(進行ロジックへ触れ、凍結成果物の再現を危険にする)、(c)CLI resumeへの組込み(resumeは保存時に全再演検証を行うため速くならない)。
- 速くならないもの: 保存(検証)、fork、resume後の保存は従来どおり全再演。高速化は読込のみ。

## 互換契約

- 保存形式・save版(17)・snapshot内容は不変。指紋scope(`league-runtime-files-v1`、12実行ファイル)も不変。新関数は`league_economy.py`内なのでsource hashは変わり、T021以前のsaveは従来どおり旧ソースで読む(identity不一致で拒否)。
- 既定の`load_league_snapshot`は完全に不変(全再演)。信頼readerはmanifest欠落、hash不一致、identity不一致、型・フィールド不一致、不変条件違反を全て拒否し、出力を作らない。
- 信頼の限界: snapshotとmanifestの両方を整合させて偽造した場合、信頼readerは規則違反の履歴を見逃し得る(不変条件と再直列化で見つかるものだけ拒否)。これは署名ではなく同一ローカルの完全性検査であり、認証が必要な場合は`load_league_snapshot`を使う。
