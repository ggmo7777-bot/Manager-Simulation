# T025 — 加齢: 年度末の記録付きイベントとして選手の年齢を進める

2026-11-10、実装前登録(結果を見る前に規則を固定)。状態: 実装前登録。担当: Claude Sonnet 5.5。着手は継続指示に基づく(T024の提案)。[事前条件](../experiments/T025-PROTOCOL.md)、判断: D040。

## 問題

M6(加齢・引退・新人)の最初の中身。T023で年度の区切り、T024で年度別順位表ができたが、選手は年を取らない。年齢は引退・新人供給・成熟曲線の前提になる。ただし年齢を足すと、`PlayerTruth`やsnapshotが変わり、既定worldのバイト同一性と保存形式に影響する。

## 最小の選択と理由

- **年齢は`PlayerTruth`に入れず**、worldの任意フィールド`player_ages`(player_id→整数)に置く。`PlayerTruth.to_dict`は不変なので、既定worldのsnapshotは1バイトも変わらない。
- 設定に任意の整数`aging_start_age`(0=無効が既定)を足す。0より大きいとき全選手がその年齢で始まる(T023の`season_length_days`>0が必須)。**有効なときだけ**configに1キー、snapshotに`player_ages`が増える。既定はキーを出さない(T023と同じ流儀)。
- 加齢は`advance_league_days`の中で、`day % season_length_days == 0`の日の通常処理の後に実行する。全選手の年齢を+1し、イベント`season_aged`(`{"season": k, "ages": {選手: 年齢後}}`)を1件記録する。進行が自分で行うので、全再演reader(`load_league_snapshot`)は設定と介入記録だけから同じ加齢を再現する。**新しい再演経路は要らない。**
- **効果は年齢カウンタの増加のみ**。技能・成長・乱数・移籍・給与・Policyへの入力は変えない(成熟曲線・衰え・引退は別task)。
- 全選手が同じ年齢で始まるのは単純化で、選手ごとの年齢分布は別task(初期分布の設計が要る)。
- 採らない案: `PlayerTruth.age`(既定のsnapshot全変更)、`season_length_days`のhook(`advance_league_seasons`)での加齢(hookは呼出し側の責任で、`advance_league_days`だけで進めると加齢されず、再演と食い違う)、save版の引上げ(有効時の任意キーだけで足り、指紋scopeの変更でsource hashは既に変わるため旧saveは旧ソースで読む既存規則に従う)。

## 互換契約

- 既定(`aging_start_age=0`)のconfig・snapshot・events・summary・manifestは不変(T018、T023基準digestと一致)。save版17と指紋scope(12ファイル)は不変。`league_economy.py`が指紋対象なのでsource hashは変わり、T024以前のsaveは旧ソースで読む(既存規則)。
- 有効時、`season_aged`イベントを除いてイベントIDを詰め直し、configの2キーと`player_ages`を除けば、同じ`season_length_days`の無効worldとsnapshotが完全に一致する。
- イベントIDは連番なので、有効時は`season_aged`以降のIDが既定とずれる。これは有効化で履歴に1件増えるという仕様で、既定には影響しない。
