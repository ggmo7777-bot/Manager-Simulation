# T041 — 選手側の自己観察の経路は利得を運ぶか(選手の意思決定の介入分解、研究者のみ)

2026-11-11、実装前登録(結果を見る前に方法・予測・失敗条件・帰属規則を固定)。状態: 実装前登録。ブランチt041はt040から積む(PR #20 → #22 → #25 → #28 の順にマージされる前提)。[事前条件](../experiments/T041-PROTOCOL.md)、判断: D056。担当: Claude Sonnet 5.5。

## 問題

T040は、監督の推定を読む4つの意思決定(先発選び・移籍・観察偵察の配分・助言)を全部、もう一方の方式の推定に差し替えても、centered_v1の先発一致の利得(+8.68pt)がほとんど動かないこと(+0.17pt / −0.43pt)を示した。simが観察雑音の方式を読む場所は、監督の観察6箇所と選手の自己観察3箇所だけなので、利得は選手側の自己観察(自己推定・疲労知覚・期待利得・信頼)を介すると推論した。これは消去法で、測定ではない。本taskは同じ介入の設計を選手側へ広げ、これを測る。あわせて、選手の独立した、理由を追跡できる判断(本プロジェクトの優先事項)の観点から、差し替えで影響を受ける判断の理由がどう変わるかを記録する。

## 最小の選択

**分析のみ。`soccer_sim/`は1バイトも変えない。新しいconfigは足さない。** 選手の各判断が読む自己観察由来の4つの状態(自己推定・期待利得[方法ごと]・コーチへの信頼[コーチごと]・疲労知覚)を、観察イベントから世界の方式ともう一方の方式の2本で厳密に再構成し、選手の意思決定の関数を呼ぶ間だけ差し替える。選手の判断は3種: **練習の選択**(practice: 方法A/B/休養)、**助言への応答**(response: 従う/部分従順/拒否と主な理由コード)、**移籍**(transfer: 移籍希望と、受けたオファーの選択)。順方向(legacyの世界にcentered_v1の自己観察)と逆方向(centered_v1の世界にlegacyの自己観察)で、1種ずつ・選手側の全3種・選手側の全3種+T040の監督側の全4種(閉包)の計12腕を走らせ、先発一致(主)への寄与を登録した規則で区間つきで帰属する。差し替えで判断(行動)と理由コードがどう変わるかを、判断ごとに記録する。最後に、centered_v1を既定にする提案の推奨を登録した規則で書く(推奨のみ。既定は変えない)。

- 対象外: `soccer_sim/`の変更、新しいconfig、既定の変更、幅の調整、第3の方式(shifted_v1)での差し替え、状態の更新規則(信頼・期待利得の学習)自体の差し替え(判断が読む値だけを差し替える)、CLI/UI。戻し方: `experiments/t041.py`、`tests/test_t041.py`、`artifacts/t041/`、文書の削除のみ。
