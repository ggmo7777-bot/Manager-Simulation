# T023 — 年度区切り(season境界)の導入: M6の最初の最小単位

2026-11-10、実装前登録(結果を見る前に規則を固定)。状態: 完了(2026-11-10、成功条件1〜6を満たす)。[結果](../experiments/T023-RESULTS.md)。担当: Claude Sonnet 5.5。着手は継続指示に基づく。[事前条件](../experiments/T023-PROTOCOL.md)、判断: D038。

## 問題

ROADMAPの次段階はM6(加齢・引退・新人・世代交代)。しかし現状のworldには「年度」の概念がなく、日数だけがある。加齢・引退・新人・毎季市場・順位表はどれも「いつ1年が終わるか」を前提にする。ゲームとしても、シーズン単位の区切りがないと順位表も世代交代も置けない。

## 最小の選択と理由

候補は(a)選手に年齢を持たせる、(b)年度の区切りを入れる。(b)を選ぶ。

- (a)は`PlayerTruth`のフィールド追加で全選手のsnapshotが変わり、既定worldのバイト同一性を壊す。年齢が何に作用するか(成熟曲線、引退条件)も決まっておらず、単位となる「1年」も未定義。
- (b)は「N日=1年度」という時間単位を、worldの状態や乱数に触れずに足せる。加齢・引退・新人・毎季市場・順位表のすべてが後でこの境界に載る。
- 設定として`season_length_days`(整数、0=無効が既定)を足し、(1) 日から年度番号と年度内日数を導く読み取り関数、(2) 年度末ごとに呼び出し側のhookを呼びながら進める`advance_league_seasons`を追加する。hookは今は何も入れない。**進行ルール・乱数・イベント・snapshotの中身は一切変えない**(有効にしてもconfigの1キーが増えるだけで、世界の履歴は同一)。
- イベントを追加しない理由: イベントIDは連番で、1件足すと以降の全ID・cause_refsがずれ、「有効にしても履歴が同一」を検証できなくなる。年度末の記録(加齢、引退等)は、その処理を入れる次のtaskがイベントとして追加する。
- 採らない案: 年度末イベントの記録(上記)、移籍窓を年度ごとに繰り返す(進行の変更になり別task)、順位表(派生物で別task)、CLIへの接続。

## 互換契約

- 既定(`season_length_days=0`)のconfig・snapshot・events・summaryは変わらない(configに新キーを出さない)。T018 rerun-py313と一致する。save版17、指紋scope(12ファイル)は不変。`league_economy.py`が指紋対象なのでsource hashは変わり、T022以前のsaveは旧ソースで読む。
- 有効時はconfigに`season_length_days`が1キー増えるだけで、それ以外のsnapshot(players、accounts、ledger、events等)は同日数の既定worldと完全に同一。
- hookはworldを変更してはならない(変更するなら呼び出し側の責任で、記録外の変更は保存・再演で拒否される)。今回のhookは呼出しの位置を決めるだけで、変更の仕組みは与えない。
