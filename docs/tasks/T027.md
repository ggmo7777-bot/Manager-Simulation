# T027 — 性格の潜在特性: 選手の真の状態としてだけ導入する最初の最小形

2026-11-10、実装前登録(結果を見る前に規則を固定)。状態: 完了(2026-11-10、成功条件1〜7を満たす)。[結果](../experiments/T027-RESULTS.md)。担当: Claude Sonnet 5.5。着手は継続指示に基づく(ユーザーの研究優先: 性格のような潜在特性を持つ個体が、理由を追跡できる自律判断をする)。ブランチt027はorigin/main(T018〜T026を含む)から切る。[事前条件](../experiments/T027-PROTOCOL.md)、判断: D042。

## 問題

CHARTERは「個体差は潜在特性・経験・状態・選択によって行動と成長に影響する。乱数や個体IDだけで代用しない」と定める。現状の`PlayerMind`には`ambition`(移籍希望・練習の動機を強める)、`autonomy`(助言を受け入れる閾値。`max(0, trust-autonomy)`)、`loyalty_bias`(移籍要求・オファー受諾を抑える)が既にあるが、sampledの`autonomy`範囲は0.32〜0.38とほぼ定数で、満足度の反応幅(試合出場+0.14、ベンチ-0.11、移籍+0.18)と休養の選好(`rest_preference=0.012`)は全選手で同一の直書き定数。つまり「同じ出来事への反応の違い」と「自己管理の違い」を生む潜在特性が無い。

## 最小の選択と理由

- **既存の3特性(野心・助言への従順/自律・忠誠)は複製しない**。ユーザー案の「野心」「協調/従順」は`mind.ambition`・`mind.autonomy`(従順の逆)として既に判断式に入っているので、新しい特性は別の2つにする。
- 追加する特性(0.15〜0.85、高いほど大きい):
  1. `emotional_stability`(感情安定性): 将来、満足度の更新幅・失望への反応の強さを小さくする向き。根拠: 満足度更新の直書き定数(+0.14/-0.11/+0.18、`decide_player_transfer_request`の`dissatisfaction`の入力)が全選手で同一。
  2. `discipline`(規律性/自己管理): 将来、疲労下の練習継続・休養指示の遵守・助言の遵守を高める向き。根拠: `rest_preference`が全選手0.012の定数で、`decide_player_training`の休養と練習の比較が個体差を持たない。
- 本taskでは**どの判断・成長・観測にも使わない**(T028で最初の利用を事前登録する)。値は選手の**真の状態**で、Policy・監督の観測には渡さない。
- **保持場所**: `PlayerTruth`/`PlayerMind`のフィールドを増やすと既定のsnapshotが変わるため、T025の`player_ages`と同じく、worldの任意フィールド`player_personality`(選手ID→{特性名: 値})とconfig任意キー`personality`(`"none"`既定、`"latent_v1"`)にする。**有効時のみ**configとsnapshotにキーが増える。
- **生成**: 既存の人口生成(`population:*`チャネル)とは別のチャネル`personality:<特性名>`で、既存の`uniform_from_key(seed, 0, チャネル, 選手ID, low=0.15, high=0.85)`の1回のキー付き決定的draw(`round6`)。キー付きハッシュで状態を持たないので、既存の乱数列・既存draw・日々の進行は構造上変わらない。選手IDはhashのトークンで、値の表は無い(IDだけでは決まらず、seedで変わる)。2特性は独立、一様分布、クラブ・選手ID・既存の野心/忠誠/自律と無関係を事前に検査する。
- **隠す**: 決定関数・Policy・観測・助言・順位表・各ループ(selection/transfer/multi_coach/state)の各moduleに特性名の参照が無いこと(AST/文字列)、および特性値を極端値へ差し替えても履歴が同一であること(動的な漏れ検査)。
- **不変条件**: 無効なら`player_personality`は空、有効なら選手集合と一致し、各値はseedと選手IDから再計算した値と完全一致(信頼readerでmanifestも偽造された改ざんを不変条件で止める)。特性値は進行中に変わらない。
- 採らない案: `PlayerMind`/`PlayerTruth`への追加(既定snapshot変更)、既存`ambition`/`autonomy`/`loyalty_bias`の改名・統合(既定を変える。統合ビューは別task)、正規分布・特性間の相関(根拠のない構造は先に入れない)、経験による特性の変化(T029以降)、クラブ・監督の性格、観測ノイズつき公開(T028以降)。

## 互換契約

- 既定(`personality="none"`)のconfig・snapshot・events・summary・manifestは不変(T018、T023基準digestと一致)。save版17と指紋scopeは不変。`league_economy.py`が指紋対象なのでsource hashは変わる(既存規則)。
- 有効にしても履歴(events含む全体)は`personality`キーと`player_personality`を除き既定と完全一致する(特性がまだ何にも使われないため)。IDのずれもない(イベントを増やさない)。
- 旧saveの読込: save17の既存snapshot(上記キー無し)は新readerでもそのまま読める。キー有りのsnapshotを旧ソースで読むことはsource hash不一致で拒否される(既存規則)。
