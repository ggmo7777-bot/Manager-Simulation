# T024 — 年度ごとの順位表(派生集計): 既存のリーグ試合イベントから導く純関数

2026-11-10、実装前登録(結果を見る前に規則を固定)。状態: 実装前。担当: Claude Sonnet 5.5。着手は継続指示に基づく(T023の提案)。[事前条件](../experiments/T024-PROTOCOL.md)、判断: D039。

## 問題

T023で年度の区切りができたが、年度ごとの勝点・勝分敗・得失点を見る手段がない。順位表はゲームの見え方の中心で、加齢・引退・新人・毎季市場(年度末hook)の入力にもなる。既にworldは`club_accounts`に通算の勝点等を持つが、**年度別ではない**。

## 最小の選択と理由

- 年度別順位表を`league_match_completed`イベントだけから導く**純関数**`league_standings(world)`として足す。状態・乱数・イベント・Policy入力・snapshotに触れない。派生物なのでsnapshot identityにも入れない(入れると保存形式とsave版が変わる。再計算できるものは保存しない)。
- 新モジュール`soccer_sim/standings.py`に置く。league_economy.py等の指紋対象12ファイルを変えないので、**ソースhash・save版・旧saveの読込は不変**、既定のバイト同一性は構造的に保たれる(それでも実測で確認する)。
- 年度の割当は`season_progress`(T023)を使い、定義を二重化しない。
- 採らない案: `club_accounts`へ年度別フィールドを足す(snapshot変更)、年度末イベントとして順位を記録する(イベントID連番がずれる。記録が要るかは年度末処理を入れる時に別途判断)、Policyや選手への順位表の公開(Policyへ渡す情報は別の境界設計)、CLI接続。

## 規則(事前登録、PROTOCOLに詳細)

リーグ試合=kind`league_match_completed`のみ。勝3・分1・敗0。順位は勝点→得失点差→総得点→勝数→club_id昇順。最後のclub_id決着は「公平な決着」ではなく決定性のための便宜なので、行ごとに`tied_with_previous`で示す。

## 互換契約

既存ファイル(soccer_sim/*.py)は無変更。snapshot/events/summary/manifest・save17・指紋scope・source hashはT023と同一。関数はworldを変更しない。

## 対象外・戻し方

昇降格、優勝判定、年度末イベント、順位のPolicyへの公開、直接対決での決着、CLI/UI。戻し方: `standings.py`と`experiments/t024.py`・テストの削除のみ。新成果物は`artifacts/t024/`のみ。
