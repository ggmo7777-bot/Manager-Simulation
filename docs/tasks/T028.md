# T028 — 性格の最初の利用: 助言への従順/部分従順/拒否を、選手本人の状態と理由つきの記録として決める

2026-11-10、実装前登録(結果を見る前に規則を固定)。状態: 実装前。担当: Claude Sonnet 5.5。T027(PR #10、未マージ)の上に積む(ブランチt028はt027から)。[事前条件](../experiments/T028-PROTOCOL.md)、判断: D043。

## 問題

T027は`discipline`・`emotional_stability`を真の状態として持たせたが、どの判断も読まないので「個体差が行動に効く」ことは未検証。現行の`decide_player_training`は助言を`advice_weight*max(0,trust-autonomy)`の加点として混ぜるだけで、助言に対する態度(従う・自分の判断と混ぜる・拒む)も、その理由も記録に残らない。CHARTERは「監督の指示は選手への入力であり直接操作ではない」「事実・観測・本人の理由・研究者の推定を分ける」と定める。

## 最小の選択

- config任意キー`advice_response`(`"none"`既定、`"personality_v1"`)。`"none"`以外は`personality=="latent_v1"`が必須(ValueError)。`"none"`以外のときのみ`to_dict`にキーを出す。
- 選手が当日1件以上の助言(提案)を受けた日に限り、**練習判断の直前**に態度を1回決める(純関数`decide_advice_response`、乱数なし)。対象は最も信頼する監督(既存の`best_prop`と同じ規則)の提案。
- 態度の式(係数は事前登録、結果後に変えない): `score = (trust − autonomy) + 0.25·(discipline − 0.5) − 0.40·(1 − emotional_stability)·dissatisfaction`。`dissatisfaction = max(0, 0.48 − playing_time_satisfaction)`(既存の移籍要求と同じ定義)。各項は`round6`、scoreは丸め後の項の和。
  - `score ≥ 0` → **complied**(従う): 提案された方法を選ぶ。
  - `0 > score ≥ −0.20` → **partial**(部分従順): 既存の判断(助言を加点として自分の期待値と混ぜる)をそのまま使う。
  - `score < −0.20` → **refused**(拒否): 助言を無視して自分の期待値・疲労・動機だけで決める。
- 本人の理由: 構造化イベント`player_advice_response`(actor=選手、`record_class: "player_reason"`)。項の値、判定、`reason_codes`(各項が|値|≥0.02のとき符号つきコード: `trust_above_autonomy`/`trust_below_autonomy`、`self_disciplined`/`self_lax`、`irritated_by_low_playing_time`、絶対値の降順)、`primary_reason`(先頭、なければ`no_dominant_term`)。
- 監督が見る記録: 別イベント`coach_advice_outcome`(actor=助言した監督、`record_class: "coach_observation"`)。キーは`coach_id`・`player_id`・`method`・`response`(選手が伝えた態度)・`stated_reason`(`trusts_coach`/`distrusts_coach`/`personal`の3値のみ。特性由来の理由は`personal`に畳む)・`action_followed`(実際に選んだ方法が提案と一致したか)。真の特性値・項の数値は含まない。**本taskでは監督のどの判断もこれを読まない**(読むのはT029以降)。
- 脚本の拒否は無い: 態度は上式の関数で、イベント・日・選手IDによる強制は無い。係数と閾値は自然な基準(trust=autonomyで従う、信頼が自律より0.20以上低ければ拒む)と、無効時(T018基準)のtrust−autonomy分布が縮退しないことの確認(特性・新機能は未使用)から固定した。ドラマ発生率や成長の改善を目標にした調整はしない。
- 採らない案: 加点`advice_weight`の係数を特性で動かす(態度が記録に出ない)、拒否を確率抽選にする(理由が追えない)、特性を監督の観測に出す(CHARTER違反)、`PlayerMind`への特性追加(既定snapshot変更)。

## 互換契約

- 既定(`advice_response="none"`)のconfig・snapshot・events・summary・manifestは不変(T018・T023基準と一致)。`personality`のみ有効(T027)の世界も、T027と完全に同じ履歴。
- `decide_player_training`へ任意引数`advice_mode`(既定`"blend"`=従来)を追加。既定の出力はキーを含め1バイトも変えない。
- 有効時は履歴が変わる(態度の結果としての行動、追加イベント、IDのずれ)。これは意図した変化。保存形式・save17・指紋scopeは不変(`league_economy.py`が指紋対象のためsource hashは変わる)。全再演readerは進行そのものを再演するので新しい読込経路はない。
- T027の静的漏れ検査の許可リストに、特性を読む唯一の新関数1つだけを追加する(T027の結論は変えない: T027時点では無効)。
