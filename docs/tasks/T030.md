# T030 — 世代交代の最初の最小単位: 年度末の引退と、同日の新人受け入れ(クラブ人数を保つ)

2026-11-10、実装前登録(結果を見る前に規則を固定)。状態: 実装前。T029(PR #12、未マージ)の上に積む(ブランチt030はt029から。PR #12が先にマージされる)。[事前条件](../experiments/T030-PROTOCOL.md)、判断: D045。担当: Claude Sonnet 5.5。

## 問題

T023(年度区切り)、T025(年齢)、T026(年齢曲線)、T027(性格)で、選手は年を取り、技能が変わり、固定の個体差を持つが、**誰も世界を去らず、誰も加わらない**。CHARTERの優先順位5(世代交代による世界の自律的変化)は未着手で、T026の年齢曲線は衰えを入れたのに、衰えた選手は永遠に残る。引退と新人は、年齢分布・人数・クラブの存続を同時に動かすので、1つずつ載せる必要がある。

## 最小の選択(引退と新人を合わせた最小の閉じた単位)

引退だけだとクラブが空になる。新人だけだと人数が増え続ける。両方を年度末の同じ日の同じ処理に置く(「引退+同日補充」)が、世界が回り続ける最小の閉じた単位。それより小さい形(引退のみ)は閉じない。

- config任意キー`generations`(`"none"`既定、`"retire_replace_v1"`)。`"none"`以外は`aging_start_age>0`が必須(ValueError)。`"none"`以外のときのみ`to_dict`にキーを出す。
- **引退規則**(`decide_retirement(*, age, playing_time_satisfaction)`、純関数。入力はこの2つだけ): 年度末の加齢(T025/T026)の直後に、クラブに所属する各選手へ適用する。
  - `age >= 36` → 引退(理由`age_limit`)
  - `33 <= age < 36` かつ `playing_time_satisfaction < 0.5` → 引退(理由`veteran_low_playing_time`)
  - それ以外は現役。
  - 乱数・選手ID・他選手の状態・真の技能は使わない。**これは未校正の仮説**で、現実の引退年齢の出典を選んでいない。年齢閾値(33/36)が主で、満足度(本人の状態、既存)は33〜35歳の範囲だけに効く。技能の傾向を使わないのは、選手ごとの技能の履歴を持つ状態が無く、追加すると別の状態設計(別のtask)になるため。性格特性は引退の根拠として正当化できないので使わない。
- **新人の受け入れ**: 引退処理の後、各クラブ(`CLUB_IDS`順)のロスターが目標人数3(初期の人数)を下回る分だけ新人を入れる。ロスターが3以上なら入れない。新人1人ごとに:
  - ID: `p{全選手数+1}`(`p13`,`p14`,…)。決定的。
  - 年齢18(定数`YOUTH_INTAKE_AGE`)。クラブは入団クラブ(`origin_club_id`=`club_id`)。
  - 技能・成長率・上限・好み・忠誠・野心・自律・自己評価の偏りは、アカデミー型の範囲(`sampled_ranges(config.range_perturbation)`の`("academy", …)`)から、**別の乱数チャネル**`population:youth_<名>`のキー付きdraw(`uniform_from_key(seed, 0, チャネル, ID)`)で生成する(既存の`population:*`の流れ・T027の`personality:*`の流れは不変)。新人は若手の型(全クラブ共通)。クラブの型は入団後の扱いに効くだけ。
  - 性格は`_personality_traits`(T027)のIDキー付きdraw。`personality="none"`なら作らない。
  - 選手の心(PlayerMind)は`_build_initial_world`と同じ初期定数(全監督への信頼0.56、満足度0.50など)。自己評価は本人の自己認識(従来どおり)。
  - **監督の初期印象は真値を使わない**: 4人の監督すべてが、技能推定0.5・試合評価推定0.5・疲労推定0.10(定数)、`last_seen_day`=入団日、残差0で持つ。その後の更新は従来の観察規則(練習観察・試合観察・偵察)だけ。
- **記録(理由つきイベント)**: `season_retired`(actor=選手、`record_class: "player_reason"`、season・player_id・club_id・age・playing_time_satisfaction・reason・rule、cause_refs=[その年度末の最後の加齢イベント])、`season_youth_joined`(actor=クラブ、season・player_id・club_id・age・reason=`roster_below_target`・roster_size_before、cause_refs=同クラブの`season_retired`、無ければ加齢イベント)。新人の真の特性値はイベントに入れない(seedから再計算できる)。
- **状態**: 新しいworldフィールドは無い。引退した選手は`players`・`player_minds`・`initial_players`・監督の評価・`player_personality`に残り(履歴を失わない)、ロスターと`player_ages`から外れる。新人は同じ辞書に加わる。現役の選手=ロスターにいる選手。加齢・引退・新人の整合は不変条件がイベント列から再計算して検査する。
- **加齢の一般化**: `generations`有効時、`season_aged`は現役の選手のみ、`season_skill_aged`の`delta`は選手ごとの辞書(新人と年上が混ざるため)。無効時は従来の形のまま。
- **使わない・変えない**: 試合・選考・移籍・給与・助言・信念のコードは年齢・引退・新人を読まない(ループが`PLAYER_IDS`固定から現役の選手に変わるだけ)。介入(`fork_league_world`)は初期12人のみ(新人への介入は対象外)。

## 互換契約

- 既定(`generations="none"`)のconfig・snapshot・events・summaryは不変(T018・T023基準、およびT029の既定と完全一致)。現役の選手の列はロスターから導くが、既定では`PLAYER_IDS`と同じ順序・同じ集合。
- `generations`有効かつ引退・新人が一度も起きない世界(開始年齢18)は、無効の世界と、config・`season_skill_aged.delta`の形式を除き完全一致する。
- 保存形式save17・指紋scopeは不変(`league_economy.py`が対象のためsource hashは変わる)。全再演readerは進行そのものを再演するので新しい読込経路は無い。信頼readerは年齢・名簿・新人の初期状態(seedから再生成)をイベントから検査する。
- T026/T027の静的検査の許可リストに新関数(年齢・性格に触れるのは新しい1関数`_generational_turnover`のみ)を加える。意味は変えない。
