# T034 — 新人の推定の遅れは観察の頻度か更新量か(規則を足さない分析。記録済みの観察イベントの数え直しと再計算)

2026-11-10、実装前登録(結果を見る前に方法・予測・失敗条件を固定)。状態: 実装前登録済み(結果前)。ブランチt034はt033から積む(PR #15、#16が先にマージされる)。[事前条件](../experiments/T034-PROTOCOL.md)、判断: D049。担当: Claude Sonnet 5.5。

## 問題

T033は、見逃された新人(真に上位2人なのに先発しなかった)の主因が、技能推定と試合評価推定の遅れ(各−0.035)であり、遅れが入団後1〜7日の−0.023から15〜21日の−0.100へ広がる(先発率は0.39前後で一定)ことを示した。次の規則を足す前に、この遅れが**観察の頻度**(新人を見る回数)から来るのか、**1回あたりの更新量**(`coach_skill_alpha`などの混合率)から来るのかが切り分けられていない。

## 最小の選択

**シミュレーションは変えない。** 各新人について、窓(入団翌日〜+21日)内の自クラブの監督の観察イベント(`coach_session_observation`・`coach_scout_observation`・`coach_match_observation`)を数え、記録された観察値から監督の推定をオフラインで再生して`lineup_decision`の推定と照合し、窓内の推定誤差を3項(最初の事前値の残り・観察時から現在までの真の成長に遅れた分・観察値のずれ)に分け、同じ追加の更新量を「観察を足す」場合と「更新量を上げる」場合でオフライン再生して比べる。結果は世界へ戻さない。

- 新規の規則・config・イベント・worldフィールド・乱数は無い(反実仮想の追加観察の雑音は既存の`uniform_from_key`と既存の`coach_noise`の式をそのまま読む)。`soccer_sim/`は1バイトも変えない。
- 対象はT033と同じ3設定×84セル(168日)。新規コードは`experiments/t034.py`と`tests/test_t034.py`のみ。成果物は`artifacts/t034/`のみ。
