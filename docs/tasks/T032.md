# T032 — 練習日の観察を監督の試合評価推定へ反映する(T031の「観察されたのに先発しない」仮説の検証)

2026-11-10、実装前登録(結果を見る前に規則を固定)。状態: 実装前。T031(PR #14、未マージ)の上に積む(ブランチt032はt031から。PR #13、#14が先にマージされる)。[事前条件](../experiments/T032-PROTOCOL.md)、判断: D047。担当: Claude Sonnet 5.5。

## 問題

T031は新人の観察率を64.4%から100%へ上げたが、先発した新人の割合は64.4%→64.0%で変わらなかった(P2反証)。T031が立てた未検証の仮説: 先発の選考は`select_skill_weight`(0.55)×技能推定+`select_match_weight`(0.48)×試合評価推定−疲労項で、試合評価推定を更新するのは試合の観察と偵察だけである。練習日の観察(`coach_session_observation`)は技能推定・疲労推定・方法の残差だけを更新するので、控えの試合評価推定は観察されても入団時の定数0.5のまま動かず、技能推定が変わっても選考の順位が動きにくい。

## 最小の選択

**練習日の観察が試合評価推定も更新する**(config任意キー`coach_practice_rating`、既定`"none"`、有効値`"blend_v1"`)。有効時のみ、`_step_training_day`の監督のセッション観察で、既存の偵察観察と同じ混合を同じ順序で使う: `match_rating_estimate ← clamp(0.70×match_rating_estimate + 0.30×観察された技能, 0.10, 0.98)`(観察された技能=その日の`c_obs_skill`、ノイズ込み)。それ以外の更新・選考規則・係数は不変。

- 更新されるのは監督のB層(`CoachPlayerEvaluation.match_rating_estimate`)だけ。入力はその日の監督の観察値`c_obs_skill`と自分の推定のみで、真の技能・特性・年齢は直接の入力にない(観察値はノイズ込みの観測で、従来の技能推定の更新と同じ経路)。乱数の追加なし。
- 0.70/0.30は偵察観察で既に使われている混合(`coach_scout_alpha`ではなく直書き定数)をそのまま再利用し、**新しい値を選ばない**。調整しない。
- 有効時のみイベント`coach_session_observation`のdataに`match_rating_estimate`(更新後)を記録する(検証用)。既定のイベントは不変。
- **別案と不採用の理由**: (a) 選考の重み(0.55/0.48)の変更: 全選手の選考を直接曲げる。観察と選考の接続を測りたいので重みは固定。(b) 試合評価推定の事前を観察で書き換える専用規則: 新しい式を作ることになる。既存の偵察の混合の再利用が最小。(c) 技能推定との統合(試合評価推定を技能推定で置き換える): 試合評価推定が持つ試合内の情報(得点・守備等の加点)を捨てる。(d) 現状維持。
