# T011-R1 修正・比較プロトコル

2026-11-07、今回のコード変更と再実験の前に登録。旧結果と不具合は既知であり、新しい未見データでの仮説登録ではない。根拠は [現状レビュー](../reviews/2026-11-07-STATUS-REVIEW.md)、判断はD026。

## 変更と成功・失敗条件

- 直接成長ボーナスを設定項目ごと削除する。現金・設備稼働・個体・認識を揃えた一歩実験で、過去の育成還元受領額だけを変えても成長・行動が不変であること。設備費を払えるかを変えた対照では、支出と稼働を経て成長差が出ること。特定の選手の移籍・成長向上や勝点改善を合格条件にしない。
- save12、rules/policy v2とし、保存・読込に全履歴の決定的再演照合を採用する。元レビューの4破損と、型違反、所有者違反、合法範囲内の状態改変、取引・契約・日境界の改変も拒否する。正常なday0、各主条件84日と42+42日、1000日+14日の継続が一致すること。
- 純粋な選手Policyの入力を本人のMindと不変の受信オファーに限定する。監督評価だけを変えても受信内容が同じなら選択が不変であること。順序反転でも不変、相手別信頼の変化やオファーの撤回で判断が変わりうること。同点は公開club ID順という暫定規則とする。

## 比較

1. 回帰テスト全件と追加テスト。正例と負例を含める。試合・旧モードは変更しない。
2. 旧T011と同じ4条件×60seed（1..30、100..129）×84日=240run、追加3条件×30seed=90run。対応seed bootstrap 2000回、係数を結果に合わせて調整しない。
3. 修正要因を分けるため、旧凍結実装上で open_solidarity の確認30seedについて「ボーナス有/無」×「私的得点同点処理/公開ID同点処理」の4条件120runを実行する。両方修正した系列が新版の集計と一致するか確認する。これは過去結果を知った後の診断実験である。
4. 短い固定状態介入で受領履歴のみの直接効果と設備稼働効果を分ける。閉ループの制度比較は移籍金・連帯金・出場配当が一緒に変わる制度パッケージの総効果であり、配当単体の因果効果とは呼ばない。
5. 口座別残高を取引イベントから独立に積算して終値と照合。再演による一致と、経済モデル自体の妥当性は区別する。
6. 84日と1000日の保存・読込時間、最大RSSを測定。旧成果物の624ファイルのサイズ/hashを前後照合（T001〜T010の545ファイル、旧T011成果物35ファイル、今回追加した旧版バンドル44ファイル。キャッシュ等除外）。

## 係数と限界

旧T011 task/D025の説明値と実装には差があった。今回は比較を狭めるため、ボーナス以外は実装値を保持する：初期現金21/59、設備費0.28、稼働倍率1.25/非稼働0.52、準備金16.5（費用支出後も維持）、移籍基本金9.5/1.5、連帯金2.5、出場配当1.25（最大6回）。旧説明値への変更理由は既存記録から確認できず、遡って正当化しない。

再演readerは日数に比例して計算費用が増え、seed・configで再生成できない記録外の途中介入を保存/再開できない。比較用の一歩介入はインメモリで行う。分岐世界の永続化には、将来、明示的な介入記録と完全な状態更新ログが必要。現時点では日28/56以外の移籍窓や世代交代はなく、1000日試験は継続性試験に限る。既存の敵対モードの「二重請求阻止」カウンタだけでは実際の重複決済APIへの攻撃を証明しない。
