# T014 — 台帳本体の整数通貨化

2026-11-08。状態: 実装・検証完了、2026-11-08ユーザー指示で採用・凍結（記録: [T014-RESULTS](../experiments/T014-RESULTS.md)）。ユーザーの「次に進んでください」に基づき、STATUSの次候補から通貨整数化だけを対象にする。実装Sol 6.1 High、設計/独立比較/記録Codex。

## 仕様仮説

- 最小単位は1/1,000,000。通貨のConfig、残高、賃金、契約額、累計、取引イベント、保存値、summaryの通貨合計をPython intにする。明示的に`*_units`へ改名し、bool/float/文字列の自動型変換を行わない。
- 人が金額を指定する補助関数は十進文字列→整数のみ。例`"0.28"`→280000。最小単位未満の非ゼロ桁・非有限数・負値は拒否し、暗黙の丸めはしない。表示は整数から十進文字列へ変換する。既存倍率は無次元なのでfloatのまま。
- 予算判定、加減算、資金保存則からround6/epsilonを除き、1単位の違いも検出する。受取先や金額の不正時、残高/累計に部分変更を残さない。
- `save15 / rules t014-integer-money-v1 / money integer-micro-v1`。判断の得点式・A/B・観測・移籍ガード・介入方式は維持。Policy版はT013と同じ（通貨API単位はsave/rules/money版で識別）。
- 旧snapshotは拒否し、旧凍結sourceで読む。自動のデータ移行は実装しない。旧成果物を上書きしない。

## 検証

- 最小単位、0.1+0.2、反復送金、残高ちょうど/1単位不足、2^53を超える整数、無効型/端数/負値、保存時の型/金額改変、通常/重複請求をテスト。
- 全unittestと高速ゲート。新タスクの低速多seedはexperimentsへ置く。
- T013と同じ経済240run（7条件×30seed＋疲労ノイズ0×30seed、84日）を比較。旧額を独立に整数へ正規化し、identity以外の全状態/全履歴・行動・結果を比較する。差が出たら最初の差を分析し、旧浮動小数の不具合を再現するために新仕様を歪めない。
- T012の5分岐×seed[1,2,3,100,101,102]（30系列）を旧版と比較。介入親hashは版/表現が違うため比較対象から除くが、値・順序・全行動/因果参照は保持する。5系列の保存再開も確認。
- 4主条件84日vs42+42日、分岐1000日+14日/連鎖介入+7日の保存再開。各取引/口座/累計を独立した整数監査で照合。
- 全旧artifactのhashを作業前後で照合。新結果はartifacts/t014に保存。

## 対象外と完了条件

hash範囲分離、直接reader、世界共通kernel、初期集団生成、経済ルール追加は行わない。通貨がintであること、保存則の厳密一致、無効入力の拒否、旧版との差の説明、保存再開、記録更新を完了条件とする。

完了結果: [T014-RESULTS](../experiments/T014-RESULTS.md)。全168テスト、経済240run/分岐30系列/1000日が旧版と正規化後に一致。
