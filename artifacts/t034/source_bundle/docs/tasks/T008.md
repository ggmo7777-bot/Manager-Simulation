# T008: 独立判断が作用する最小の2D競技核

状態: **実装・検証完了**。2026-11-07。ユーザーからの着手指示を受け、[事前計画](../experiments/T008-PROTOCOL.md)を実装前に登録し、実装・自動テスト・比較実験・独立監査を完了した（[結果](../experiments/T008-RESULTS.md) / [レビュー](../experiments/T008-REVIEW.md)）。T007までの育成環境は作り直さず保持している。

> **作成者に関する明記**: T001〜T007の作成者（`Sol 6.1 High` および当時の主担当）とは**別の作成者である Antigravity（Gemini 4 Argon）** が、本T008の事前計画策定・実装・実験・独立監査を担当した。

## 目的と最小範囲

育成と相手別認識の境界は検査できたが、現時点ではサッカーをプレーできない。最初は独立した2対2の短い競技エピソードを提案する。VS1の3対3とは別の、移動・パス・シュートと対戦相手の存在を検査する小さな単位。4選手・1ボール・2ゴール・固定tick、描画なし、標準ライブラリ/CPUを第一候補とする。

位置と技能、個人の観測と方針を分け、全選手が同じtickの自分の観測から意図を出してから競合を解決する。監督の戦術AIは接続せず、必要なら固定の方針メッセージだけを入力する。毎tickの動作は本人が選ぶ。既存の1技能をパス/走力/シュートすべてにそのまま転用せず、競技fixtureに必要な最少能力を明示する。育成との対応付けは後の判断。

## 実装前に決めること

1. 格子2Dと連続座標2Dを、競合解決の明瞭さ・位置取り・保存の費用で比較する。初回は連続2Dを有力案とするが固定仕様ではない。
2. ボールを所持/地上移動で表すか、パスを短い遷移で抽象化するか。奪取、同着、境界外、得点後再開、時間切れのルールを小さく定義する。行動順やIDで所持を独占しない。
3. 局所観測の範囲と、不可視対象をunknownとして扱う方法。相手の能力・意図・記憶を真値としてPolicyに渡さない。研究用oracleは別条件にする。
4. 行動は移動/パス/シュート/待機など最少集合にする。速度/到達距離と実行誤差のどこに能力が作用するか明記する。空間を無視した勝敗抽選にしない。
5. 観測と行動の型、乱数キー、保存/再開点、試合ログの粒度と版。社会世界全体や未知の3D向け抽象を持ち込まない。

## 今回の選択と実装契約（Antigravity / Gemini 4 Argon）

1. **空間表現**: 連続座標2Dピッチ $(x, y) \in [-10.0, 10.0] \times [-6.0, 6.0]$（ゴール幅 $y \in [-1.8, 1.8]$、固定tick、標準40tick/エピソード）を採用。4選手（`home`: `h1`, `h2` / `away`: `a1`, `a2`）と1ボール。
2. **ボール遷移と競合解決**: ボールは座標・速度・単一所有者（`owner_id`）を持つ。同時行動で複数人が制御半径 $r_{\text{ctrl}}=0.85$ に入った場合は距離・能力・キー付き乱数による対称スコアで判定し、異チーム間の完全同点はID順を使わず中点へのルーズボール（`mutual_rebound`）とする。非保有者の `pass`/`shoot` 意図は `illegal_without_ball` として記録し `hold`（移動0）へ落とす。
3. **局所観測と非漏洩**: 視野半径 `vision_radius=6.5` 外の他選手座標は `unknown`（`visible=False, position=None`）とし、相手の真の能力（`pace`, `passing`, `shooting`）・私的スタイル・当tick意図は一切Policyへ渡さない。研究用 `oracle` 条件のみ全位置をノイズ0で観測する。
4. **最小能力と行動集合**: 育成の1技能を流用せず、`MatchTraits(pace, passing, shooting)` と私的 `MatchStyle(directness, pass_bias, press_bias)` を分離。行動は `move`, `pass`, `shoot`, `tackle`, `hold` の5種。
5. **保存と旧成果物保全**: `world_kind='match_2d'`, `save=8`, `rules='t008-match2d-v1'`, `policy='t008-match2d-score-v1'` として独立保存し、T001〜T007の凍結成果物（340ファイル）と既存の育成CLI条件を完全保持する。

## 完了条件と比較

- 不正な二重所持、範囲外の値、過大移動、無費用の複数行動、無原因の得点がない。非保有者のキックなど不可能な意図の扱いを検査する。
- Policyへ真値が漏れず、隠れた相手能力を変えても観測が同じ時点の意思決定は不変。実行結果は能力変更で変わってよい。
- 対称fixtureの左右反転、ID/処理順交換で対応する結果が一致。同点の規則が非対称なら理由と感度を明示する。
- 同じ初期状態で位置・実行能力・Policyのうち1要因だけを変える介入を用意する。成功パス、奪取、シュート、所持推移、行動分布を測り、得点だけで合否を決めない。
- 全員シュート反復、ボール近傍待機などの単純対照で一動作が無条件に支配しないか調べる。攻略があれば条件と履歴を残し、個体差が無意味なら核を修正する。
- 同seed、連続/保存再開で状態・ログ一致。短いエピソードから位置とボールの動きを後で再生できる。実行時間/ログ量を測る。
- T001〜T007の凍結成果物を保持。実験結果と限界を記録し、育成との接続を次に進められるか判断する。
