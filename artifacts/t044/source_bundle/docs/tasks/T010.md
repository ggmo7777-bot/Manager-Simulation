## 問題と目的

T009では1クラブ内で「育成（`A/B`）$\leftrightarrow$ 監督の先発選考 $\leftrightarrow$ 2D競技」の閉ループを構築・検証したが、対戦相手が固定基準チームであり、[ROADMAP.md](../ROADMAP.md) のM4 / VS1が掲げる循環の最終要素：

`監督の観察/提案 → 選手の受諾/代替行動/休息 → A/Bの更新 → 監督の先発選考 → 2クラブ直接2D競技 → 監督の評価/選考・選手の出場満足度の更新 → 希望/交渉/成立した場合の所属変更（相互合意移籍） → 新環境での次の学習機会と出場`

がまだ検証されていない。特に [CHARTER.md](../CHARTER.md) および [OPEN-QUESTIONS.md](../OPEN-QUESTIONS.md)（`Q10`）が求める通り、**固定イベント移籍を一切作らず、選手本人・獲得側監督・放出側監督の3者の独立した主観認識と利害がすべて合致したときのみ所属変更が成立すること**、そしてその移籍が選手個人の出場機会・成長軌跡および2クラブ間の直接対決成績をどう変えるかを検証する必要がある。

## 実装前に決めることと今回の選択（Antigravity / Gemini 4 Argon）

1. **2クラブ・2監督・6選手の最小構成と所属人数不変条件**:
   - クラブ `club_a`（監督 `c1`）は初期所属 `p1, p2, p3`（3人）、クラブ `club_b`（監督 `c2`）は初期所属 `p4, p5, p6`（3人）とする。
   - 各クラブは試合日（Day `7, 14, ..., 84` の計12試合）に所属選手から先発2名（`slot 0`, `slot 1`）を選出し、`club_a`（`home`）対 `club_b`（`away`）の40 tick直接2D試合（`match_2d`）を行う。
   - どの時点でも各クラブの所属人数は `2 <= len(roster) <= 4` を満たさなければならない（先発2枠を常に確保するため、2人クラブからの単方向放出は不可）。
2. **育成日の監督行動（自クラブ指導＋他クラブ視察 `scout`）と選手行動**:
   - 各監督 `c1, c2` は育成日（`day % 7 != 0`、計72日）に1日2枠を持つ。自クラブ所属選手に対する `observe`（前後観察付き練習セッション）・`propose`（方法 `A`/`B` の提案）に加え、他クラブ所属選手1名の練習を視察して自身の私的評価 $\hat{s}_{c, i}, \hat{m}_{c, i}$ を更新する `scout`、または `rest` を選べる。
   - 各選手 `p1..p6` は1日1枠を持ち、**現在所属しているクラブの監督からの提案のみ**を受け取って `A`, `B`, `rest` を自律選択する（他クラブ監督の提案は届かない）。実際に採用・実施した助言については所属監督に対する信頼 `trust_by_coach[coach_id]` を更新する。
3. **移籍窓口（Day 28, Day 56）における3者相互合意移籍プロトコル**:
   - Day `28`（第4節終了後）と Day `56`（第8節終了後）の試合後処理の直後に移籍窓口（`transfer_window`）を開く。
   - `transfer_mechanism='disabled'` では窓口での交渉を行わない。`'enabled'` では以下の4段階をすべて私的認識のみから評価する（真の能力・学習率は一切参照しない）：
     1. **選手の移籍希望 (`player_transfer_request`)**: 選手 $i$ の移籍希望得点 $U_{\text{req}}(i) = 0.55 \cdot (0.48 - \text{satisfaction}_i) + 0.08 \cdot \min(4, \text{bench\_streak}_i) + 0.20 \cdot (\hat{s}_{i,\text{self}} - 0.42) - \text{loyalty\_bias}_i$ が閾値 $\theta_{\text{req}} = 0.08$ を超えると移籍希望を表明する。
     2. **放出側監督の放出同意 (`releasing_coach_consent`)**: 現在の所属クラブの人数が `> 2` であり、かつ所属監督 $c_{\text{from}}$ の選考スコアにおいて選手 $i$ が自クラブ内3位以下（控え評価）または先発2番手との差が一定以下で放出余剰スコア $U_{\text{rel}}(c_{\text{from}}, i) \ge 0.0$ のとき放出に同意する。
     3. **獲得側監督の獲得オファー (`target_coach_offer`)**: 相手クラブの人数が `< 4` であり、獲得側監督 $c_{\text{to}}$ の私的評価における選手 $i$ の戦力価値 $\hat{V}_{c_{\text{to}}}(i) = 0.55 \hat{s}_{c_{\text{to}}, i} + 0.48 \hat{m}_{c_{\text{to}}, i}$ が、相手クラブの現在の先発2番手の評価 $\hat{V}_{c_{\text{to}}}(\text{starter\_2nd})$ を閾値 $\theta_{\text{offer}} = 0.025$ 以上上回るとき獲得オファーを出す。
     4. **選手のオファー受諾 (`player_offer_acceptance`)**: 選手 $i$ が移籍先での期待出場機会（公開試合履歴から観測される移籍先クラブの先発平均評価に対する自己評価の優位度）と移籍先監督への信頼から受諾得点 $U_{\text{acc}}(i, c_{\text{to}}) > 0.0$ と判断したとき、**3者合意が成立**し原子的に所属が `club_a -> club_b`（または逆）へ変更される。
4. **保存・版・過去成果物の保全**:
   - `world_kind='transfer_loop'`, `save=10`, `rules='t010-transfer-loop-v1'`, `policy='t010-transfer-score-v1'`, `author='Antigravity (Gemini 4 Argon)'` として独立保存する。
   - 1パス線形整合監査readerを実装し、T001〜T009の凍結成果物（485ファイル）を完全保持する。

## 主比較と追加対照

- **主比較（$2 \times 2$ 要因計画、4条件×60seed×84日＝240run）**:
  1. `decoupled_stay`: 育成能力の試合反映OFF × 移籍窓口OFF
  2. `coupled_stay`: 育成能力の試合反映ON × 移籍窓口OFF
  3. `decoupled_transfer`: 育成能力の試合反映OFF × 移籍窓口ON
  4. `coupled_transfer`: 育成能力の試合反映ON × 移籍窓口ON（M4後半の最小2クラブ閉ループ）
- **単一要因の追加対照（確認30seed `100..129`、計90run）**:
  5. `fair_c1_prior_p3`: `coupled_transfer` に対し、所属監督 `c1` の `p3` 初期評価のみを過小評価 `(0.32, 0.30)` から適正 `(0.50, 0.54)` へ変更（`p3` が `club_a` で先発起用されるため不満が生じず、移籍が起きなくなるかを検証）。
  6. `low_c2_scouting_p3`: `coupled_transfer` に対し、相手監督 `c2` の `p3` 初期評価のみを `(0.48, 0.50)` から低評価 `(0.31, 0.29)` へ変更（`p3` が移籍希望を出しても `c2` がオファーを出さず移籍不成立となるかを検証）。
  7. `high_loyalty_p3`: `coupled_transfer` に対し、`p3` のクラブ愛着 `loyalty_bias` のみを `0.00 -> 0.35` へ変更（`p3` がベンチでも移籍希望を出さず残留するかを検証）。
