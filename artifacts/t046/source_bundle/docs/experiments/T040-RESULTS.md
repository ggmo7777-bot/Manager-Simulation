# T040 結果 — どの意思決定が推定の水準のずれを受け取って利得になるか(介入による分解、分析のみ)

実施: 2026-11-11。契約: [T040](../tasks/T040.md)、事前条件: [PROTOCOL](T040-PROTOCOL.md)、判断: [D055](../DECISIONS.md)。`soccer_sim/`は凍結T037 source_bundleとバイト一致(config追加なし、既定は`legacy`のまま)。T037〜T039と同じ3設定×84セル×168日で、12腕(順方向6・逆方向6)を実行(3,024実行、ゲート用の素のcentered_v1を252加えた)。実行: `uv run --python 3.13.3 python -B experiments/t040.py --out artifacts/t040/run`(約15分、8プロセス)。全実行は1回だけ(失敗した全実行はなし)。

## 結論(平易に)

1. **監督の推定を読む4つの意思決定(先発選び・移籍・観察偵察の配分・助言)を全部、もう一方の方式の推定に差し替えても、先発一致の利得はほとんど動かない。** 順方向(legacyの世界に全4チャネルでcentered推定を渡す)は+0.17pt [−0.48, +0.84]で、動的な利得D = +8.68pt [+7.37, +10.00]の2%(f_all = 0.02 [−0.06, +0.10])。逆方向(centered_v1の世界に全4チャネルでlegacy推定を渡す)でも−0.43pt [−1.20, +0.34](r_all = −0.05)で、centeredの利得は消えない。登録した帰属規則の判定は **`outside_coach_estimates`**(利得の過半は監督の推定を読む意思決定の外にある)。
2. **単独のチャネルにも担い手はいない。** 先発選びは順方向で**悪化**(F −1.34pt [−1.98, −0.66]、3設定とも負)、助言は順方向で+1.50pt [+0.74, +2.25]だが逆方向では−0.97pt [−1.76, −0.26](符号が逆で担い手にならない)。移籍(−0.02pt、−0.13pt)と配分(−0.35pt、−0.07pt)は約0。`harm(lineup)`、`harm(advice)`の旗が立った。
3. **コードを読んだ事実(測定ではなく消去法)**: simの中で`observation_noise_mode`を読むのは、監督の観察(練習・試合・偵察の雑音と疲労)の6箇所と、**選手の自己観察**(`self_obs`の雑音、`training_self`と`match_self`の疲労)の3箇所だけ。監督の推定を読む決定関数はこの4つで全部なので、全4チャネル差し替えの腕は監督側の差をすべて除いたことになり、残る約8.5ptは**選手側の自己観察の経路**(自己推定・疲労知覚・期待利得・信頼 → 選手の練習の選択・助言への応答・移籍希望とオファーの選択)にあると考えられる。これは消去法による推論で、選手側を差し替えて測ったものではない(T041の候補)。
4. **監督側の意思決定が運ぶのは、結果指標(先発一致・最終技能)ではなく練習枠の使い方**(登録の記述指標): centered_v1の世界では、練習枠の`propose`が−7.1pt、`scout`が+6.8pt(偵察の件数は+78.5/セル、+17%)。このうち助言のチャネルだけで−4.2pt/+4.0pt(約58%)、全4チャネルで−5.1pt/+5.0pt(約72%)が再現される。T036から知られていた「偵察+17%」は、助言(`propose`の候補)の評価が水準のずれを受け取る監督側の効果。助言の差し替えは先発一致を順方向で+1.50pt動かすが、centeredの世界でlegacy推定を助言に渡すと先発一致がむしろ+0.97pt上がる(最終技能も+0.0013上がる)ので、centeredの利得の機構ではなく、他の経路との相互作用の可能性が高い(未検証)。
5. **既定をcentered_v1にする提案の推奨は、登録の規則で「条件つき」。** Dは有意(下限+7.37pt)で最終技能も劣らない(+0.0057 [+0.0040, +0.0074])が、帰属が`outside_coach_estimates`、f_all < 0.5、`harm`ありで「推奨」の条件を満たさない。条件は、利得を運ぶ選手側の経路を特定すること(T041)。

## 既定を`centered_v1`にする提案の推奨(提案のみ。既定は変えない)

登録の判断規則: 「推奨」は、帰属が`single_route`・`multiple_routes`・`distributed`・`partial_single`のいずれか、かつf_all ≥ 0.5、かつ3設定ともD>0、かつ最終技能・最終信頼の差の区間の下限がともに≥0、かつ`harm`なし。「条件つき」は、Dの下限>0かつ最終技能の差の下限≥0だが推奨の条件のどれかを欠く。結果: Dの下限+7.37pt、最終技能の差の下限+0.0040、最終信頼の下限+0.0041、3設定ともD>0。帰属は`outside_coach_estimates`、f_all = 0.02、`harm`あり。**規則では「条件つき」**。

読み方: 「条件つき」は「利得は本物だが、機構が監督側ではなく選手側にあるらしく、まだ特定されていない」。centered_v1の結果指標(先発一致+8.7pt、最終技能+0.0057、信頼+0.0050)の利得は、どの監督側の意思決定にも帰属されないまま、T036/T037のとおり残る。既定の移行提案に残る条件は、選手側の自己観察の経路(自己推定・疲労知覚・期待利得・信頼 → 選手の決定)を特定すること。偵察+17%は監督側の助言のチャネルが運ぶと分かったので、新しい基準での再測定の対象として扱える。移行には凍結成果物(T018以降の基準)の置換・再基準化が伴う。

## 正直な注記(解析の自由度を含む)

- **実装前に、帰属規則の抜け(主経路が2つ以上)を訂正した**(PROTOCOL末尾に記録。コードも結果も無い段階)。
- 開発中の短い世界の試走で、記録用の`uniform_from_key`ラッパーがキーワード引数(新人の生成の`low`/`high`)を通さないバグを見つけ、全実行の前に直した(結果は見ていない)。全実行は1回で、登録した統計はすべて報告した。事後の指標は足していない。
- 「消去法」(結論3)はコードを読んだ事実とゲート4・5の厳密性に基づく推論で、選手側の差し替えを測ったものではない。全4チャネル差し替えの腕は「centered_v1の世界の部分的な再現」ではなく(観察の配分が変われば観察される選手も変わる)、順方向と逆方向を併せて見る理由。
- 全4チャネルの差し替えの腕とcentered_v1の実走との差は、選手側の経路に加え、**この2つの相互作用**(F・Rは加法的でない)を含む。i_Rの区間の上限は0.28で、相互作用が小さいとは言い切れない。設定別のi_Rはt031 0.24、t032 0.30。
- centered_v1は平均だけでなくばらつきも半分にする(T037: 平均+7.0pt、ばらつき+1.7pt)。本taskの「centered推定」は両方を含み、平均だけの帰属は`shifted_v1`での差し替え(対象外)で別途必要。
- 先発一致への帰属のみが規則に使われる。昇格率・練習枠の変化の解釈(助言がpropose↔scoutを動かす理由は、propose候補の「需要」が技能推定の水準に依存するためと思われる)は記述にとどまり、理由は検証していない。世界は3seedを共有し独立でないので区間は過小の可能性がある。ロスターは3人(先発2人、控え1人)。
- 差し替えは決定の瞬間の評価値だけで、世界の本物の推定は常にsim本体が更新する。

## 次の候補(実装ではない。別task、未着手)

**T041(候補): 選手側の自己観察の経路の介入分解。** 同じ差し替えの枠組みを選手側へ広げる。選手の自己推定・疲労知覚・期待利得・信頼を、`self_obs`と`training_self`/`match_self`の観察イベントから世界の方式ともう一方の方式の2本で厳密に再構成し(厳密性ゲートは本task同様)、選手の意思決定(練習の選択・助言への応答・移籍希望・オファーの選択)を1種ずつ差し替える順方向・逆方向の腕で、先発一致・最終技能・信頼のDのうち各決定が運ぶ割合を測る。全4+全選手側チャネルの閉包で、監督側+選手側がDをどれだけ再現するか(残差)を出す。その後に、既定の移行提案を判断する。
