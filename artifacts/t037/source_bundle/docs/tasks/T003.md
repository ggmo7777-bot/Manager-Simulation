# T003: 観測経験に基づく助言への信頼

状態: **実装・検証完了**。2026-11-05の継続指示により着手。同日35テスト・240run・保存再開の検査を完了。M2の最初の部分であり、複数監督・選考・キャリアの完成ではない。[事前計画](../experiments/T003-PROTOCOL.md) / [結果](../experiments/T003-RESULTS.md) / [主担当確認](../experiments/T003-REVIEW.md)。

## 問題と最小仮説

T002までは信頼が固定値だった。今回、選手が実際に受け取った助言と自分の観測を使い、監督の予測への信頼を更新する。その信頼が次の助言への反応を変えるか検証する。

ここでの信頼は **実施した方法の成長予測について、監督が自分より当てになったと感じる程度** に限定する。好意、服従心、約束への信頼、客観的な指導能力とは別。未知の代替練習の結果は使わない。

## 作るもの

1. 監督の主観的な方法別成長率の事前信念。最初は両方法とも0.10。真のrate/capから作らず、独立した誤りうる知識として保存・初期eventに記録する。今回この事前信念自体の学習は行わない。
2. 練習提案に予想gainを付ける。候補式は `q_coach = subjective_rate[method] * (1 - perceived_skill)`。入力は監督自身の能力評価と事前信念だけ。疲労・真の上限を無条件で知っている設計にしない。
3. 選手は受け取った提案を従来どおり自分で採用/拒否する。予測値を今回の即時行動得点へ直接追加しない。新たな作用経路は経験からの信頼更新に限定する。
4. 助言した方法を実施した場合だけ、朝夕の私的な技能信号の **符号付きの差** と、行動前の自己予想gain/受信した監督予測を比較する。自己予測はその方法のGの更新前の値。
5. 信頼を更新して保存し、次回の判断に使う。助言がなかった/拒否した/休息した場合は更新しない。拒否を自動罰にしない。
6. 信頼の前回event、自己のGの根拠、受信提案、選択、朝夕観測、予測誤差、更新量を辿れる履歴を残す。

## 試用する更新式

```text
y = self_signal_after - self_signal_before
loss_self = (y - q_self_before_action)^2
loss_coach = (y - q_coach_received)^2
evidence = clip((loss_self - loss_coach) / scale^2, -1, 1)
trust_next = clip(trust_before + step * evidence, 0, 1)
```

暫定値は`step=0.05`、`scale=0.05`。現実の心理モデルやBayes更新ではなく、相対予測誤差に反応する検証用仮説。推定の正しさを真値で採点する仕組みではない。2予測が同じなら、観測ノイズがあっても信頼は変化しない。

T002のGの非負切り詰めは維持する。信頼更新のyには適用しない。Gの推定に残る偏りが自己予測との比較に影響しうることを結果の限界に含める。符号付きGへの変更や同点処理変更を同時に混ぜない。

## 境界と受入

- Configから信頼更新を有効/無効にでき、設定と式/版を保存する。通常の旧baselineは無効を維持し、新しい実験/run条件で有効にする。
- 新しい情報/参照を記録するためsave/rule版を上げる。T001/T002を新readerで黙って読まない。
- 信頼更新無効のとき、T002と数値/行動/採点が一致する（新しい予測と参照の記録は比較から除く）。
- Policy/信頼更新へWorld、潜在適性、真のgain、未選択行動の結果を渡さない。
- 更新に使用した自己予測と監督予測の時点を明示する。新しいGで過去の自己予想を置き換えない。
- 小さな改善は実装担当が判断可。信頼の意味/式/経路を変える場合は根拠と代替を親担当に連絡する。

## 対象外

監督の方法別事前信念の学習、多次元の人間関係、会話、複数監督、起用/移籍、競技、加齢、C、LLM、UI。信頼の上昇/低下・拒否・関係崩壊の発生を脚本として保証しない。
