# T036 結果 — 観察雑音の中心化 `observation_noise_mode`(既定`legacy`、`centered_v1`は明示選択)

実施: 2026-11-11。契約: [T036](../tasks/T036.md)、事前条件: [PROTOCOL](T036-PROTOCOL.md)、判断: [D051](../DECISIONS.md)。方法・定義・予測は実装前にコミットし、結果後に変えていない(実行前に追記した「clampなし観測」の定義の明確化を除く。下の注記)。Python 3.13.3(uv)。T033〜T035と同じ3設定(T030/T031/T032の有効設定)×84セル×168日を`legacy`/`centered_v1`の2群で実行(504実行)。**既定は`legacy`のまま。変更は雑音の式だけで、乱数のキー・回数は同じ。**

## 結論(平易に)

1. **仕組みは設計どおり動く。** `legacy`群は3設定×84セルの最終値・イベント数が凍結結果と252/252一致し、凍結T035のsource_bundleを別プロセスで動かした6セルともスナップショット全体(identityを除く)のhashが一致した。`centered_v1`では観察の誤差(観察値−真の技能)の平均が練習日−0.0004、偵察−0.0002、自己−0.00004(`legacy`は−0.0245/−0.0301/−0.0181)に、clampが起こり得ない疲労観察の誤差も5つの文脈すべてで|平均|≤0.001になった。
2. **ただし`centered_v1`は「平均だけを直す」のではない。** 元の式`(u−0.5)×2×幅`は範囲が[−3幅,+1幅](長さ4幅、標準偏差1.155幅)で、`u×幅`は[−幅,+幅](長さ2幅、標準偏差0.577幅)。**平均が0になると同時にばらつきが半分になる**。事前に「変えるのは平均だけ」と書いたが、ばらつきの変化を予測に入れていなかった(T035のP8で標準偏差が半分になることは書いていたが、本taskの予測には反映しなかった)。以下の結果は、平均の補正とばらつきの減少が混ざった効果である。
3. **推定は全体として良くなった(MAEが下がる)。** 新人以外の技能推定のMAE 0.0638→0.0575、新人(入団後1〜21日)0.0606→0.0551、3設定とも下がる(セル対でMAEが下がるのは新人以外247/252、新人246/252)。**T035の予測(新人以外は悪化)は外れ**。新人以外の平均誤差は+0.0002→−0.0013で、約+0.013にはならなかった。「別の正の偏り」は雑音のばらつきと一緒に小さくなったと考えられるが、**未検証の仮説**(分解には、平均0でばらつきが元のままの対照が要る。T037候補)。
4. **悪化した点もある。** 新人以外の試合評価推定の偏り+0.0152→+0.0182(3設定とも正方向へ、さらに過大)、T030設定の新人以外の技能推定の偏り−0.0046→−0.0084。新人の15〜21日の誤差は−0.1008→−0.0911で**まだ−0.09**(遅れは直らない)。
5. **先発の的確さが大きく変わった(予測外)。** 記録された先発が真の上位2人と一致する割合は62.3%→70.9%(+8.7pt、3設定とも上がる: +12.2/+9.9/+3.9)。新人の先発割合は38.8%→38.4%(−0.5pt)とほぼ不変。
6. **最終結果も少し動く(予測外)。** 168日後の技能+0.0057(0.765→0.771、158/252セルで上昇、p=7e-5)、信頼+0.0050(0.468→0.473、186/252)。満足度(−0.0013)と移籍数(+0.02)は区別できない。T030/T031/T032の別々では技能の差はp=0.16/0.0014/0.038。観察イベントのうち偵察は+17%(466→544件/セル)、練習日の観察は+8%、全イベントは+0.10%。
7. **判断**: ゲートは全て通る(下)ので`centered_v1`は**版つきの選択として採用(試用)**。**既定は変えない**。既定を移すかは、平均とばらつきを分けた対照(T037候補)を見てから別taskで決める。

## 変更箇所

- `LeagueEconomyConfig.observation_noise_mode`(`"legacy"`既定 / `"centered_v1"`、他は拒否)。configの辞書にキーが出るのは既定以外のときだけ。
- 技能観察4箇所(自己`self_obs`、監督`coach_obs`、偵察`scout_obs`、試合`match_obs`)は関数`observation_noise(u, 幅, mode)`を通す。`legacy`は`(u−0.5)×2.0×幅`を式のまま(ビット同一をテスト)、`centered_v1`は`u×幅`。
- 疲労観察は`league_observation.observe_fatigue(..., centered=False)`の任意引数。`legacy`は`(2u−1)×幅`、`centered_v1`は`u×幅`。5呼び出し(自己の練習・自己の試合・監督の練習・偵察・監督の試合)がconfigの値を渡す。
- `uniform_from_key`の呼び出し(AST上 league_economy 6、league_observation 1)は凍結bundleと同数・同じキー。旧selection_loop/transfer_loop/match_2dは無変更。

## 限界・正直な注記

- **平均とばらつきが混ざっている。** 本taskの`centered_v1`は平均を0にし、標準偏差を1.155幅→0.577幅に下げる。精度の改善(MAE、先発の的確さ、最終の技能)のどれだけが平均の補正で、どれだけがばらつきの減少か、本taskでは分けられない。T035の線形伝播(平均のずれだけの効果)の予測が外れたこと(新人以外の悪化)も、ばらつきの減少で別の正の偏りが小さくなったとすれば説明がつくが、**未検証の仮説**(例: 推定が高い選手ばかりが観察・起用される選択のバイアスは、雑音のばらつきに比例して大きくなる)。
- 事前登録の「変えるのは雑音の平均だけ」は不正確だった。乱数のキー・回数が同じという点は正しい。
- 「clamp除く」の定義(真の疲労≥幅 かつ 真の疲労+幅≤0.95)は実行前に追記したもので、legacyの[−3幅,+幅]を考慮していなかった。事後の集合は探索的と明示した。
- 試合観察の基準値`perf_raw`は記録されないので、試合の観察誤差は直接測らず推定の誤差で見た。自己観察の誤差は試合のない日のみ。
- 行は新人×試合日で独立でなく、3seedも独立でない。ロスターは小さい。偵察イベントが増えた理由(推定の分布が変わり偵察の判断が動く)は調べていない。
- 疲労観察は(centeredでも最大25%が)下限0に当たるので、centeredでも平均誤差は正(clamp込み +0.0003〜+0.0087)。

## 作者向けのメモ(短い、平易な日本語。どこにも投稿していない)

> 観察の雑音のコードに、移植時の取り違えらしいずれがありました。`league_economy.py`の自己・監督・偵察・試合の4か所の観察と、疲労の観察(`league_observation.py`)が、`uniform_from_key`の既定範囲[−1,1]をそのまま`(u−0.5)×2×幅`などと使っているため、雑音が[−3幅,+1幅]になり、平均が「−幅」ずれています(練習日で約−0.024、偵察で約−0.030)。旧モジュール(selection_loop、transfer_loop、match_2d)は全て`low=−幅, high=幅`と明示した対称範囲で、設計の文書にも偏りを意図する記述は見つかりませんでした。
> これを新しい設定`observation_noise_mode`(既定`legacy`=今までと全く同じ履歴、`centered_v1`=対称な雑音)で選べるようにしました(PR #19)。既定は変えていないので、これまでの結果は動きません。`centered_v1`にすると、推定の誤差(MAE)は新人も新人以外も下がり、先発が真の上位2人と一致する割合は62%→71%、最終の技能は+0.006でした。ただし、直すと雑音の平均だけでなくばらつきも半分になるため、どちらの効果かはまだ分かりません。次はその切り分けを提案します。
