# EXP-T001 実装・検証結果

CPython 3.13.3、macOS arm64。標準ライブラリのみで実行した。比較は事前登録どおりの seed 0〜29 を使い、係数を比較結果に合わせて再調整していない。

## 実行したコマンド

```sh
python3 -m unittest discover -s tests -v
python3 -m soccer_sim run --seed 17 --days 28 --out artifacts/t001/baseline
python3 -m soccer_sim run --seed 17 --days 14 --out artifacts/t001/first_half
python3 -m soccer_sim resume --snapshot artifacts/t001/first_half/snapshot.json --days 14 --out artifacts/t001/resumed
cmp artifacts/t001/baseline/snapshot.json artifacts/t001/resumed/snapshot.json
cmp artifacts/t001/baseline/events.jsonl artifacts/t001/resumed/events.jsonl
python3 -m soccer_sim experiment --out artifacts/t001/experiments
python3 -m soccer_sim run --seed 17 --days 1000 --out artifacts/t001/stress_1000
```

テスト11件が合格。1000日のテストでは各日で選手2人が1枠ずつ使い、監督の予算超過、同日同一対象への観察・提案の重複、イベントIDと参照の不整合が0件。真の状態と認識の範囲を各日終了時に検査した。対象外の選手や行動、超過枠、非有限の設定、未知の版、不正な原因参照を拒否した。

seed 17の28日連続・14日保存後に14日再開した実行は、全572イベントと状態が一致し、両方の `cmp` が終了コード0。別の同seed連続実行との完全一致も自動テストで確認した。正規化した状態・履歴のSHA-256は `c4757774d5958043f794c0d966b8c7ccb49bf987e7adfde3354e89467f2eac19`。

## 実装ノート

- **世界と判断入力**。世界は技能、上限、方法別rate、疲労、各個体の私的認識を保持する。判断関数には選手・監督別の不変DTO、本人の信念、共有の採点係数を渡す。真値と観測の由来を含む研究ログは世界側に置く。2人の技能はともに0.38、疲労は0.08から開始する。p1は上限0.87、rate A/Bが0.145/0.035、p2は上限0.91、rateが0.045/0.13。好み、自己推定、自律性、信頼にも差を設定した。
- **時間と観測**。選手1人1枠、監督2枠。監督は観察・提案・休息を比較し、各行動で1枠を使う。同じ選手に対する観察と提案はそれぞれ1日1回まで。有料観察は選手行動前の技能を標本とし、監督の評価への反映は夕方とした。選手には朝の技能・疲労の信号と自分への提案が届く。選手全員の判断を確定してから結果を反映する。初期値と配点の全体は `simulation.py` と各実行のmanifestにある。
- **Aの成長**。練習は `min(cap−skill, rate×duration×focus×(1−fatigue)×(cap−skill))` を真の技能に加える。durationとfocusはともに1。翌朝の疲労は練習なら `clamp(fatigue+0.25−0.13)`、休息なら `clamp(fatigue−0.42−0.13)`。休息の日に技能は増えない。0.13は自動睡眠回復。
- **Bの更新**。朝夕の技能信号の差を0〜1に収め、練習した方法の予想利得をその値へ50%寄せる。選手の技能自己推定を夕方の信号へ45%、監督の推定を有料観察の信号へ48%寄せる。標本のノイズは一様に振った値を真値に足して0〜1に収める。振幅は技能の自己観測0.025、体感疲労0.025、監督観測0.065。ノイズ0では上記3振幅を0にする。推定更新の手法は移動平均。CのPolicy・重み学習は未実装。
- **選手の判断**。方法の得点は `予想利得 + 好み − 0.045×体感疲労`。提案された方法にだけ `0.055×(信頼−自律性)` を加える。休息は `0.14×体感疲労`。最高得点を選び、提案があれば採用・拒否を記録する。自己技能の推定は今回の採点項に使っていない。
- **監督の判断**。観察は `0.15×min(未更新日数/6,1)+0.04×(1−推定技能)`。提案は `0.12×(1−推定技能)+0.05×方法適合`。方法適合はAなら `1−推定技能`、Bなら推定技能。休息は固定0.035。同点は候補列の先頭を選ぶため、ロスター順の影響は残る。IDを採点値には使用しない。
- **再現性**。乱数はSHA-256から作る53 bitの一様値で、キーは `(方式版, root seed, channel, day, actor_id, draw_index)`。外生ノイズのキーを対応seedで共有し、観察の有無や真値の違いにより観測結果は変わりうる。永続する乱数状態はroot seedとキー方式のみ。正規化hashには時刻・出力先を含めず、状態、全履歴、設定、ソース指紋、ルール・Policy・乱数・保存の版を含める。ソース指紋は `soccer_sim/*.py` の内容から算出し、変更後のコードで古いsnapshotを読む場合は明示的に拒否する。

## 仮説別の確認

| 仮説 | 観測結果 |
|---|---|
| H1 同じ練習でも潜在適性が効く | 上限・初期技能・疲労・方法・時間を揃えた無ノイズの1枠で、rate 0.145と0.045のgainは0.069368と0.021528。rateを両方0.095にするとgainは両方0.045448。 |
| H2 信頼が助言の効果を変える | B提案の同じ判断で、信頼0.2ならAを選び拒否、0.8ならBを選び採用。Aの得点は0.05275のまま、Bは0.034から0.067。予想利得のみを動かして選択が変わる別テストも合格。 |
| H3 観測経験が次の選択に効く | 合成した二つの履歴で、A/Bの観測差を0.09/0.01と0.01/0.09にした。次の観測と初期信念が同じでも、B更新ありでは予想利得が0.07/0.03と0.03/0.07、選択がAとBに分かれた。B更新停止では両方0.05/0.05でA。 |
| H4 隠れた状態の非漏洩 | 初期技能・認識・観測を固定し、p1の潜在rateとp2の真の上限を変えた。初日の監督・選手の候補得点、選択、入力参照は一致し、p1の真の技能変化には差が出た。 |
| H5 再現・再開 | 28日連続と14+14日で状態、全履歴、hashが完全一致。 |
| H6 閉ループの整合 | 4条件×30seed×28日の比較を完走。seed 17で1000日完走し、日予算とイベント参照の全件検査に合格。 |

追跡例は基準のseed 17、1日目のp1。真の成長イベント17から、練習Aの実行15、意思決定13、朝の自己観測5、監督の提案9、私的信念1を参照できる。候補得点はA 0.07979、B 0.06074、休息0.01013。IDは計算上の参照関係を表す。

## 対応seedによる比較

各行は28日×30本、計840日・1,680選手枠。技能gain・自己/監督誤差は60人分の終了時平均。個体差は各run内の2人の最終技能の絶対差の平均。助言採用率の分母は提案数。時間はシミュレーション本体、ログ容量は同じ形式で出力する場合のJSONLバイト数を各条件で合計した値。

| 条件 | 平均技能gain | A / B / 休息 | 助言採用 | 自己誤差 / 監督誤差 | 平均個体差 | 秒 | ログ bytes |
|---|---:|---:|---:|---:|---:|---:|---:|
| 基準 | 0.39483 | 33.0% / 41.1% / 25.9% | 560/1,140 (49.1%) | 0.00949 / 0.02915 | 0.06383 | 0.215 | 7,180,734 |
| rate均質 | 0.41691 | 39.2% / 35.8% / 25.1% | 563/1,140 (49.4%) | 0.01010 / 0.03704 | 0.03970 | 0.216 | 7,183,708 |
| B更新停止 | 0.31847 | 41.3% / 37.2% / 21.5% | 90/150 (60.0%) | 0.31347 / 0.30847 | 0.03603 | 0.224 | 7,179,624 |
| ノイズ0 | 0.40559 | 25.0% / 48.2% / 26.8% | 600/1,140 (52.6%) | 0.00350 / 0.02126 | 0.09764 | 0.214 | 7,109,250 |

- rateを方法別の2人平均にすると平均gainが増え、個体差は縮んだ。上限、好み、信頼と選択の差は介入後も残る。同じ練習でのrate単独の効果はH1のプローブで測った。
- B更新停止では監督の「評価に使った最新の観察日」も初期日のままになり、観察の配点が高止まりした。監督は30本で観察1,530回、助言150回を選んだ。基準では観察540回、助言1,140回。技能や採用率の条件差には監督の配分変更も含まれる。選手の経験による選択変化はH3のプローブで切り分けた。
- ノイズ0でも2人に0.09764の最終技能差が残り、基準より平均差は広がった。ノイズ0条件では30seedすべてで最終技能のペアが同一だった。
- 監督の休息は4条件で0回。候補として採点しているが、今回の設定では一度も選ばれていない。監督自身の疲労・休息の効果はモデルに含めていない。

## 1000日実行と限界

| 日数 | 本体秒 | イベント数 | JSONL bytes | snapshot bytes |
|---:|---:|---:|---:|---:|
| 28 | 0.009 | 572 | 238,888 | 240,557 |
| 1,000 | 0.248 | 20,336 | 8,756,833 | 8,758,524 |

同じseedの28日から1000日へ延ばすと、ログは約36.7倍。snapshotに全履歴を同梱するため、ログとsnapshotを合わせて約17.5 MB。長期の容量・再開時間の評価は、履歴を分離する段階で行う。1000日終了時には技能がほぼ上限に達した。加齢や環境変化がない今回の成長式の帰結であり、技能やキャリアの長期モデルとしての妥当性は未検証。

H1〜H6は機構の確認。設定した2人・1技能・2方法、仮想履歴、単一コード・Python環境を対象とする。実際の育成、人間の認知・信頼、試合・選考やキャリアへの一般化、異なる環境間での完全一致は未検証。閉ループでBの効果を次に切り分ける候補は、選手の利得推定だけを凍結し、監督の観察と評価更新を維持する比較。
