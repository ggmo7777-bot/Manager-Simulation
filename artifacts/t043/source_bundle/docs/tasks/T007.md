# T007: 複数監督の私的な認識と相手別の信頼

状態: **実装・検証完了**。2026-11-06。T006完了後の継続指示で着手。[事前計画](../experiments/T007-PROTOCOL.md)を実装前に登録。83テスト・240run・独立監査の[結果](../experiments/T007-RESULTS.md)と[レビュー](../experiments/T007-REVIEW.md)を保持する。以下は着手時の問題・契約として読む。

## 問題と目的

T006までに1監督の観察→予測学習→方法選択と、選手の採用/拒否→経験→信頼の循環を確認した。しかし監督は1人で、信頼は単一値のため、「誰を信じるか」「誰が何を知らないか」はまだ比較できない。

次は2監督と少数選手に限定し、監督ごとの観察・知識・時間予算と、選手から相手への信頼を分ける。試合・契約・移籍の完成は前提にしない。同じPolicyでも私的状態の違いで提案が分かれ、経験を共有しない相手の知識/信頼へ更新が漏れないことを先に検査する。

## 最小範囲の候補

- 監督IDごとの状態/観測/予測補正/行動枠。選手の信頼と根拠を相手別に保持する。
- 同じ選手への異なる提案を扱い、選手は独立に自主練習・助言採用・休息を選べる。
- 提案元と実施経験の帰属を明示し、誰の何の予測を評価したか履歴から追えるようにする。
- 監督の私的経験を交換/固定する機構比較と、相手別信頼を固定する比較。初期の能力差だけで監督の優劣を決めない。
- 既存1監督モードの旧結果を保全し、同じ人数・予算内の比較を先に行う。

## 着手前に決める事項

1. 2監督から同時に助言を受ける方式と、一定期間の指導相手を選ぶ方式を比較し、初回に必要な一方だけを採用する。
2. 同じ方法を複数人が提案した場合、本人が受け取った予測と経験から誰の信頼を更新できるか。未受領/未実施の助言に結果を割り当てない。
3. 監督人数の追加による観察資源の増加と、知識/関係を分ける効果を混同しない対照。
4. 初期の監督の違いを何に置くか。予測事前知識と観察機会を最小候補とし、性格軸を一度に増やさない。
5. 同時刻の処理順、同点処理、予算、保存版と旧reader、ログ量。Protocolに先に記録する。

## 今回の選択と実装契約

期間ごとの指導相手変更は選定周期や切替費用を別に要するため、今回は同時に受領した助言を扱う。2監督×1枠/日、2選手×1枠/日。監督は各自の朝の認識だけで独立に行動し、他監督の選択/観測を読まない。観察は各自の私的な前後信号を得る。重複観察も費用を払う。

選手の方法別得点は既存式を基礎とし、同方法を勧めた中で信頼最大の1提案だけを助言項へ使う。加算/多数決はしない。実施方法に一致する受領済みの予測はそれぞれ経験と照合できるため、2提案が一致していたなら相手別に2回の信頼評価を行う。未実施方法、未受領の予測、他選手の経験は評価しない。負の助言項や同点処理は事前計画に明示する。

新しい複数監督の世界型・個人状態・保存を用途に即して小さく分離し、既存の成長/信号/予測/信頼評価/監督Policyの関数を共有する。新選手状態には使われない単一trustを残さない。旧1監督コードは比較基準として保持し、全面の多監督化や過剰な汎用化を同時に行わない。

Sol 6.1 Highの担当は新機構・必要な共有境界/CLI・テスト・T007実験出力・RESULTS。主担当はProtocol/契約/全体資料/独立レビュー/凍結保存を管理する。旧artifactは変更しない。標準ライブラリ・CPUのみ、再帰委任なし。重要な設計差は実装前に根拠と代替を連絡する。71件の既存テスト、旧4条件240本照合も維持する。

## 成功・失敗条件

同じ真値でも観察が違えば監督の認識・提案が異なる余地があり、選手の経験が相手別の評価に作用すること。未経験の他監督へ知識や信頼更新が自動伝播したら失敗。根拠なしに相手を切り替える乱数、拒否への自動罰、対立の強制は採用しない。

機構・時間・非漏洩・保存再開を確認し、監督の誤り/機会の偏りを含めて報告する。競技や長期キャリアの成立とは区別する。この境界が成立したらM3の2D少人数競技、M4の選考と所属/機会の循環へ進む。
