# EXP-T002 実装・検証結果

2026-11-04。CPython 3.13.3、macOS arm64、標準ライブラリのみ。事前登録の探索 seed 0〜29、確認 seed 100〜129 を使い、セット間で係数を調整していない。各条件28日、各セット210本、計420本。

## 更新の分離と検証

- **G** は実施した練習の方法別期待値を更新する。朝夕の私的観測、実施方法を選んだ判断、その方法の前回記憶を参照する。A/Bそれぞれに記憶IDを持つ。
- **S** は夕方の自己観測から自己技能推定を更新する。選手の採点では参照しない。
- **C** は有料観察から監督の技能推定を更新する。**R** は同じ観察があった日を独立に記憶する。監督は技能評価を観察と提案の候補で、観察日の記憶を観察候補の採点で使う。
- 4フラグは実験条件・snapshot・setupイベントで明示し、Policyの入力は観測・信念・採点係数のままとした。有効になった更新だけを個別イベントとして残す。Aの式、Policyの配点・同点規則、観測ノイズ、利得の切り詰め、初期プロフィールを維持した。
- 保存版を2、ルール版を `t002-training-v2` に更新した。保存から再開するときは元の4フラグを復元する。T001のsnapshotは現行コードで拒否し、T001の凍結コードで再開すると基準のsnapshotとJSONLにバイト一致した。

- **G停止**では、確認セットの個体別gain差がp1 −0.01397 [−0.02326, −0.00564]、p2 −0.06748 [−0.08028, −0.05453]。各runの観察/提案総数18/38は維持したが、p1への平均提案は22.60→17.20、p2へは15.40→20.80。G停止から続く監督の反応を含む閉ループの総効果であり、提案列を固定した直接効果は今回測っていない。
- **C停止**では、確認セットで監督の平均絶対誤差が0.02975→0.44278へ増えた一方、平均gainも増えた。観察は両者とも各runで各選手9回、提案はp1/p2で28/10回となった。評価の精度と、このPolicy・プロフィールでの技能gainは別々に変わった。
- **R停止**では、両セットで1run当たり観察18→51、提案38→5。実際の最終観察は両選手とも28日目だが、記憶された日は0のまま。確認セットの監督平均誤差は0.02009。Rだけ止めたときのgain差は正で、同じ提案総数だった全停止のgain差は負だった。
- **S停止**は、確認セットの自己推定平均誤差を0.00774から0.39056へ増やした。現Policyの判断に使わない推定を停止しても、成長履歴は同じだった。

## 観測差と同点のprobe

真の技能0.4、成長0、独立な観測ノイズ振幅0.025、EMAの初期値0・係数0.5、各seed64更新。seed 0〜999で同じ朝夕観測に切り詰めと符号保持を適用した。

| 更新 | 64回後の平均 | 個別推定値の経験的95%範囲 |
|---|---:|---:|
| 負の観測差を0へ切り詰め | 0.008640 | [0.000212, 0.025406] |
| 符号を保持 | 0.000342 | [−0.023422, 0.022879] |

範囲は個別seedの終端推定値の2.5/97.5百分位で、平均の信頼区間ではない。内点・独立一様ノイズ `±a` では観測差の正部分の期待値は `a/3`。64更新後の切り詰めEMAの理論平均はほぼ0.008333、符号付きEMAは0。ノイズ0は両方0。符号反転した対称標本では、切り詰めの終端は+0.05と0、符号保持は+0.05と−0.05だった。符号付き方式は独立probeに限定した。

選手の候補A/Bは得点0.05で同点。現選択はA、最大値を取る入力を逆転するとB。監督の2人への観察候補は0.174で同点。現選択は先頭のp1で、ロスターを逆転するとp2。同点集合を正規順にして循環する独立probeは、固定の2候補・12ターンで両順序ともp1/p2へ6回ずつ配分した。変動する候補集合での公平性は未検証で、現行Policyの同点処理は維持した。

## 実行と性能

```sh
python3 -m unittest discover -s tests -v
python3 -m soccer_sim experiment --suite t002 --out artifacts/t002/experiments
python3 -m soccer_sim experiment --suite t001 --out /tmp/soccer-t002-legacy-suite
```

自動テスト21件が合格。7条件すべてについて、CLIでも `run --condition <条件名> --seed 17` で28日と14日を出力し、後者を `resume --days 14` で進めた。各条件のsnapshotとJSONLを `cmp` で照合し、両ファイルが一致した。旧snapshotの再生テストはT001凍結ソースを作業ディレクトリとして `python3 -B -m soccer_sim resume` を実行し、一時出力をT001基準と比較した。

比較420本の本体時間の合計は約2.85秒。28日×30本の条件別本体時間は約0.19〜0.22秒、同等の全履歴をJSONLに出す場合の容量は6.40〜7.72 MB。実際の `comparison.json` は約2.05 MB。
