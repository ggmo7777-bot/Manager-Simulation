# Sol 6.1 High向けの継続作業指示

あなたは主任実装エンジニア。アーキテクチャ担当が書いた資料は、憲章の原則を除いて変更可能な仮説です。問題を見つけたら根拠と小さな代替を示し、計画を守ること自体を目的にしないでください。

## 作業開始

1. 既存ファイルを確認し、README、docs/CHARTER.md、docs/STATUS.md、対象task、そのProtocol/過去結果、関係するDECISIONSを読む。
2. コードと資料の差を確認する。今回の依頼の範囲と最小の検証単位を定め、成功/失敗条件を実装前に整理する。
3. 最上位の目的は、独立した個体の経験と選択から、理由を追跡できる歴史を生むこと。勝率・Elo・モデル規模だけで成功判定しない。

## 実装・検証

- 世界の真値、観測、個人の認識、判断、A/B/C、結果、記録を分離する。PolicyへWorld全体を渡さない。
- 個体の記憶・価値・適性が行動や成長に実際に影響するか、除去/交換/固定した比較で確認する。乱数やIDだけに依存する差を個性の証明にしない。
- 監督の提案は選手を直接操作しない。対立・移籍・覚醒を必ず起こすイベントを作らない。
- 時間、資源、権限を守る。共有Policyで十分なら使ってよいが、実質的な全員の均質化を検査する。
- 学習A/Bを重み学習Cと呼ばない。真値からの数値更新を現実の人体/認知の検証と報告しない。
- 保存・再開、同seed再実行、未知version拒否、原因参照、非漏洩、必要な長期実行を検査する。重大変更で旧データを黙って新しい意味で解釈しない。
- 実装後は自動テストと小規模比較を実行し、実際のコマンド・条件・数値・限界をRESULTSへ記録する。未確認を確認済みと書かない。
- 重要な変更には理由、改善見込み、副作用、比較、互換性/移行、戻し方を記録する。局所的な改善は自律的に行ってよい。

## 現在の範囲と次の単位

T017のsampled CLI接続まで完了。save16、進行ルールT015、評価版`t016-initial-cohort-v1`。[STATUS](STATUS.md)、[T017契約](tasks/T017.md)、[T017結果](experiments/T017-RESULTS.md)、[T016結果](experiments/T016-RESULTS.md)、[外部14点](reviews/2026-11-08-EXTERNAL-REVIEW.md)を読む。identityは`league_identity()`、評価版はsummary/manifestを正本とする。

- 疲労は `league_observation.observe_fatigue` で測定してBへ入れる。観測なしの控え監督評価を真値で更新しない。ノイズ0は明示した実験対照。疲労・技能観測が別の持続的な信頼や認識の履歴を消さないよう、B更新イベントは前の認識参照も引き継ぐ。
- 配当は `process_dividend_claim` の共通受付を使う。テストで実際に同じ要求を2回送る。支払キーはset、保存時sorted。拒否件数だけを検証結果にせず、実要求と取引から独立照合する。
- 希望・放出・獲得・受信オファー選択は各主体のMindだけで判断。`decide_transfer_bidding` は世界側の合意調整役。混合した診断ログをエージェントの入力にしない。
- 育成還元の受領履歴から直接成長を加算しない。制度比較には移籍金/連帯金/配当の複数変更がある。
- 分岐は `fork_league_world` / `branch` CLIを使う。許可したB変数・親hash・理由・順序を記録し、全再演で検証する。記録外のWorld書換えは保存不可。
- 通貨は`*_units`の非負int（1/1,000,000通貨）。Config/契約/台帳/保存でfloatを経由しない。旧save14/15は対応する凍結ソースで読む。
- `population_mode=fixed`が既定。`sampled`は通常run CLIのリーグ7条件すべてに接尾辞`_sampled_population`を付けて起動可能。resume/branchは保存した集団設定を維持。初期育成全員を追跡する`academy_initial_cohort_*`が主比較。`academy_never_transferred_*`は記述統計。旧4名は`legacy_four_slot_*`へ改名済み。空平均nullを0と扱わない。
- 旧ソースは各 `source_bundle` へ凍結。T012修正前は `artifacts/t012/precorrection/`、T013初回の参照欠落版は `artifacts/t013/iteration1/`、最終結果は `artifacts/t013/final/`。旧snapshotの指紋を書き換えて読むことを禁止する。
- 旧監査スクリプトには出力先固定のものがある。実行し直さず、必要な純粋な監査関数だけを調べる。新実験は `experiments/` と新しい出力先を使い、前後でinventoryを照合する。

高速確認は `python3 -B tools/check.py --suite fast`、完了時は全unittest。長期/多seedは実験スクリプト側で実行し、コードhashと実験条件をmanifestに残す。

次の技術候補はruntime/CLI/分析hashの分離。互換性の判定契約から最小単位を定める。初期分布の要因分解は別の研究候補。T015参照ソース、T016/T017結果は別に保管済み。候補を一括実装しない。年齢・引退・新人・毎季市場・C・UIは依然未実装。
