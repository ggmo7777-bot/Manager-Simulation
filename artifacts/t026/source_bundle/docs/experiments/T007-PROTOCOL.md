# EXP-T007 2監督の私的認識と相手別信頼

登録: 2026-11-06、実装/結果観察前。目的は、誰が何を知り、誰のどの予測を評価して選択を変えたかを分離すること。現実の監督能力・好意・服従・長期キャリアの妥当性はこの検査だけで確定しない。

## 範囲と実装境界

2監督c1/c2、既存と同じ2選手p1/p2、1技能、A/B/休息、84日。監督1枠/人/日、選手1枠/人/日。監督の総予算は2だが、旧1人2枠とは配分自由度が異なるため、主たる因果比較は**同じ2監督・同じ予算**の内部で行う。

単一WorldState/PlayerMindの全面置換と、目的を限定した複数監督の型・進行を追加する案を比較した。既存は1coach/scalar trustの履歴検査と密結合のため、後者を試す。新しい状態は、1組だけの選手真値・自己認識、監督IDごとのCoachMind、選手→監督の信頼と根拠を持つ。単一trustの影を残さない。

共用するのは既存の成長処理、signal、EMA、方法期待更新、coach_forecast/coach_experience/evaluate_feedback、監督Policyなどの意味が同じ関数。旧日進行を丸ごと複製する汎用エンジンは作らない。CLI/保存は世界種別を明示し、旧1監督の既定と軌跡は維持する。複数世界型の統合は必要性を測って後に判断する。

実装前レビューで新readerの検査を具体化した。複数監督のsave7は初期fixture/config・現在state・全eventを保存し、型/範囲/版を検査後に初期条件から日進行を再演して現在stateと履歴全体を照合する。複雑な専用履歴validatorの重複を減らす暫定方式。**読込費用は過去日数に比例する。** 保存状態だけを直接読む一定時間のcheckpointではなく、記録外の途中介入も未対応。1000日の読込費用を測り、将来の長期規模では状態復元と監査を分ける。再演一致だけで機構の正しさを主張せず、独立な手計算/非漏洩/帰属テストも行う。

## 初期条件

- 選手の真の技能/上限/方法率、自己推定、方法期待、好み、自律性、疲労はT006の2プロフィールと同じ。方法期待Gはsigned。
- p1のc1/c2への信頼は両方0.75、p2は両方0.28。相手間で初期の好悪を作り込まない。
- c1の主観的な方法率はA=0.12/B=0.04、c2はA=0.04/B=0.12。各監督の技能評価はp1=0.32/p2=0.46で同じ、初期補正は0。この率は知識の事前仮説で、真の選手率ではない。
- 監督は同じforecast_rank Policyを使用する。固定率の違いと後の私的経験から判断が分かれる余地を作り、優れた監督を保証しない。
- その他のA/B・疲労・観測振幅・学習係数・信頼更新式はT006と同じ。

## 日内順序と情報

1. 選手が自己の朝信号を得る。
2. 各監督はその朝までの自分のMindと公開ロスター・残り1枠から、observe/propose/restを独立に決定する。全員の判断を先に計算する。他監督の当日行動や観測を次の監督へ渡さない。
3. 行動を確定して各自の予算を払う。観察者だけが対象の私的前信号と事前A/B予測を予約する。提案は対象選手へ伝わる。監督間の通信はない。
4. 選手は自分への全提案を受領し、自分の1行動を選ぶ。全選手の選択後に世界の成長/疲労を処理する。
5. 選手の自己後信号を取り、朝の自己予測と相手別の事前予測を評価してから自己Gを更新する。
6. 観察した監督だけが自分の後信号を得る。各自の予約した事前予測と実施方法を照合して補正・技能推定・鮮度を更新する。休息は方法の失敗標本にしない。

監督信号の乱数キーはchannelにcoach_idを含め、player_id/day/前後で一意に分ける。選手のキーは従来と同じ。共有する世界の結果から後日に他者が影響を受けることと、私的認識の直接漏洩を区別する。

## 選手の独立判断と経験の帰属

方法mへの受領提案の中から、朝の信頼が最大の提案をscore_sourceとして選ぶ。同信頼はcoach_idの固定順。同点順は出所ラベルに影響しうるが、同じ信頼値の助言得点は等しい。受領順・監督の処理順で得点を変えない。

```text
rest_score = 0.14 * felt_fatigue
method_score = self_expected_gain[m] + preference[m]
               - 0.045 * felt_fatigue + advice_term
advice_term = 0, when no received proposal recommends m
advice_term = 0.055 * (trust[score_source] - autonomy), otherwise
```

係数は旧式を維持する。信頼が自律性より低い場合、助言項は負になる。助言を無視して同じ方法を自主選択する別候補は今回は追加しない。この反発を含む式と、独立な意図/交渉を表現できることは別である。方法と休息の同点順は従来どおり。

ログでは以下を区別する。

- **received**: 実際に受領したcoach_id/proposal_id/方法/予測。
- **score_source**: 候補の助言項に使った1相手と、その信頼根拠。
- **method_match**: 選手が実施した方法と一致した受領提案。単に一致したことを服従の動機と断定しない。
- **feedback_eligible**: 実際に実施した練習と方法が一致し、事前に受領済みの予測。休息/別方法/未受領には評価なし。

同方法を両監督が提案して実施されたら、本人は両予測を同じ観測結果と照合できる。各edgeを別々に既存evaluate_feedbackで更新し、一方の更新結果を他方の入力に使わない。両方に自動的な加点をする規則ではなく、各予測の相対誤差で増減する。未選択の別方法の結果は捏造しない。T003〜T006の単一提案のacceptedという語と集計上混同しない。

## 主比較

全条件で2監督各1枠、前後観察ON、自己G signed、自己/監督技能・鮮度更新ON、forecast_rankを共通にする。

| 条件 | 監督の予測補正 | 相手別信頼 |
|---|---|---|
| multi_frozen_fixed | 更新OFF | 固定 |
| multi_frozen_adaptive | 更新OFF | 経験更新 |
| multi_learning_fixed | 更新ON | 固定 |
| multi_learning_adaptive | 更新ON | 経験更新 |

84日×4条件×60seed＝240run。探索0..29、確認100..129、係数調整なし。同じ初期集団で観測誤差を変える比較。数値対照は各学習設定内のadaptive−fixed、各信頼設定内のlearning−frozen、交互作用`learning_adaptive - learning_fixed - frozen_adaptive + frozen_fixed`。対応seed単位bootstrap 2,000回、解析seed7007、95% percentile区間。欠損は0にせず有効組数を示す。

行動の不一致は対応する2条件の実際の行動列から算出。選手・監督を別々に測り、不一致率の交互作用は作らない。相手別の信頼差・経験差を測り、世界を一つの多様性点数で最適化しない。

## 機構検査と独立対照

| 検査 | 受入 |
|---|---|
| 監督の私的認識 | 同じ真値でも別観測で認識が分かれうる。c1の観測/補正だけ変更し、同時点のc2入力と判断は不変 |
| 相手別信頼 | 同方法で異なる予測を受領したfixtureでは片方の信頼を上げ他方を下げられる。両方とも朝のtrust/自己予測を参照 |
| 帰属 | 未受領/別方法/休息/他選手への提案にはfeedbackなし。同方法を受領し実施した場合はscore_source以外も自身の予測で評価 |
| 判断の独立 | 受領提案/自分の記憶を固定してWorldの真値・監督の未送信私的記憶を変えても選手判断は不変。各監督も他者心を読まない |
| 時間/重複 | 各監督1枠、選手1枠。重複観察にも両方費用。同日2行動/未払い観察/選手の直接操作を拒否 |
| 順序/対称性 | 提案入力順と監督処理順の反転で意味のある状態/行動が不変。ノイズ0で監督のプロフィール割当を交換し、相手ラベルを対応づけて比較 |
| 共有原始関数 | 固定した1提案・対応するtrustなら旧選手得点と一致。A/予測/信頼の手計算・前後の時点も一致 |
| 保存 | 4条件84日vs42+42日のsnapshot/JSONL一致、相手所有者違いの参照・不正値/欠落設定/未知種別や版を拒否 |
| 旧世界 | T006の4条件240本の状態/履歴を照合し、旧artifact hash不変。旧readerで代表保存を再開可能 |

主比較とは別にノイズ0の4条件をseed17・84日実行し、乱数をなくしても作用が残るか報告する。プロフィール交換/順序/同方法二重評価は固定fixtureの機構検査であり、普遍的な集団効果ではない。learning_adaptiveを1000日実行して保存読込・追加14日と予算/参照を確認する。

## 採否と今回の停止点

成功条件は情報の所有者、判断と実施の帰属、相手別の経験更新、独立判断、履歴/継続。監督間の対立、信頼の逆転、成長増の発生を保証しない。破損や漏洩があれば修正して再実験し、仮説を取り替えた理由を残す。

CLIから起動/再開できる研究用の最小環境として保存し、既定の1監督を無断で置き換えない。結果/REVIEW/設計/STATUSを更新してT007を終える。競技、選考、契約/移籍、C、UI、監督同士の通信、指導相手を選ぶ長期契約は今回は未対象。
