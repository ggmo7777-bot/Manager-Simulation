# 設計・実験・変更の管理

## 情報の置き場所

| 情報 | 正本 |
|---|---|
| 上位目的・禁止方向 | [CHARTER](CHARTER.md) |
| 現在の構成案と交換境界 | [DESIGN](DESIGN.md) |
| 未決判断と変更の影響 | [OPEN-QUESTIONS](OPEN-QUESTIONS.md) |
| 順序・ゲート | [ROADMAP](ROADMAP.md) |
| 現在実装されたこと/次の最小単位 | [STATUS](STATUS.md) |
| 重要な判断・理由・戻し方 | [DECISIONS](DECISIONS.md) |
| 実装契約 | `docs/tasks/Txxx.md` |
| 実験の事前条件と結果 | `docs/experiments/Txxx-PROTOCOL.md` / `Txxx-RESULTS.md` |
| 実測・履歴・snapshot | `artifacts/<task>/<run>/`、manifestを併置 |

資料の「実装案」を実装済みと読まない。結果は資料の完成度より、再実行可能なコマンドと保存された証拠を優先する。AI Work Memoryには重要な判断/結果/場所を補助的に記録し、そこが使えなくてもリポジトリから再開できるようにする。

## 各タスクの手順

1. 憲章、現在状態、関係する判断と過去の失敗を読む。
2. 仮説、変更変数、固定条件、成功/失敗、測定、対象外を短く記入する。
3. 最小実装と必要なテストを行う。
4. 同条件のbaselineと介入を実行し、全試行と版を残す。
5. 仮説を支持/反証/判定不能/未実施に分け、限界と副作用を記録する。
6. 設計維持または修正を決め、STATUS、関連設計、次タスクを同期する。

## 重要な変更の記録書式

```text
ID / 日付 / 状態（提案・試用・採用・撤回・置換）
問題と根拠: 実測、失敗、該当する実装/資料
変更対象: どの仮説・状態・境界か
候補: 少なくとも現状維持と別方式
予想される改善:
副作用・失うもの:
比較対象・実験・判定条件:
互換性: save、rule、Policy、obs/action、modelのどの版が変わるか
移行/戻し方: 旧データと旧コード、再実験方法
結果と判断: 未実施なら未実施と明示
```

最上位目的を変更するときはユーザーに確認する。局所実装の改善はその都度確認で止めず進めてよい。状態表現、AI役割、学習、競技モデル、保存の意味が変わる場合は、アーキテクチャ担当が記録と計画の更新を引き受ける。担当モデルの回答自体を証拠にはしない。

## 実験runの最小manifest

T001はseed、設定、日数、日予算、コード指紋、ルール/Policy/乱数/save版、実行環境、結果hashを出力する。今後branch実験を作る時点で、親snapshot hash、介入時点/変数、初期集団hash、外生入力、依存版、学習重み/optimizer版、評価コード版を追加する。

同じseedでもコード・条件・乱数の呼出し方が異なれば同じ実験とはみなさない。過去の結果を新しい式で上書きせず、新runとする。バグ修正で旧結論が無効になった場合は、旧結果を削除する代わりに「無効化理由」と代替runを記す。

T001のソース指紋はpackage内全Pythonファイルを対象とするため、実験コードだけの修正でも旧snapshotを拒否する。安全側の暫定仕様であり、将来は実行ルールと分析コードの版を分離する候補。移行を実装する前に拒否を回避して読み込まない。

## 因果説明とバイアスの扱い

- 比較条件のうち何を実際に変えたかを列挙する。B更新を全停止したなら、選手だけの効果と説明しない。
- 人数やseed、評価期間を結果を見て都合よく選び直さない。追加した比較は探索的と明示する。
- 映像/記事に向く一例だけで合格を決めない。全体集計と例示を分ける。
- 単純な式の期待通りの動作は機構の検証。現実の認知/育成に関する科学的妥当性は別問題。
- 失敗を消すためにドラマ発生率の直接報酬や強制イベントを追加しない。

## 長期保存への段階移行

初回は全履歴入りsnapshotを保持し、ソース一式の保管も行う。サイズが問題になる段階で、データは追記区画、checkpointは状態＋log末尾参照、索引は再生成可能な派生物に分ける。snapshotとイベントのまとめ書込みの整合、部分破損、途中中断、重複取引、migration往復をテストする。

現段階の単一ファイル原子的置換は、runフォルダ全体のトランザクションや電源断からの完全復旧を保証しない。後者を必要とする規模に進む前に保存プロトコルを検証する。
