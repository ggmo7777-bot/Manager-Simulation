# T001: 選択・育成・認識・再開の最小閉ループ

状態: **初回実装・検証完了**。以下の契約は着手前に記録したもの。対象は28日、選手2人、監督1人。フルVertical Sliceの最初の部分。[結果](../experiments/T001-RESULTS.md) / [主担当確認](../experiments/T001-REVIEW.md)。

## 仮説と今回の終点

共有された単純な判断関数でも、個人の信念・価値・状態が異なれば選択が異なり、隠れた学習特性と実際の経験が能力変化を変える。この差を事後にログから追跡し、保存・再開して同じ続きを計算できる。

今回は1種類の技能と2種類の練習方法でよい。試合、選考、移籍、世代交代、ニューラルネット、LLM、UI、経済、動的な性格・信頼形成は作らない。信頼は選手の持続的な主観値として選択に使用し、信頼の変化モデルは次段階で検証する。今回の成長差を「キャリア分岐を実証した」と呼ばない。

## 実装境界

- Python 3.13系で確認できた環境、標準ライブラリのみ。インストール不要で `python3 -m soccer_sim ...` を実行できる配置。
- 推奨する小さな分割: `state.py`、`observation.py`、`policy.py`、`simulation.py`、`storage.py`、`experiments.py`、`__main__.py`。必要なら統合/分割し、過剰な基底クラスやプラグイン機構は避ける。
- `WorldState` は真の技能、潜在学習率/制約、疲労、個体の認識を所有する。Policyの引数に渡さない。
- プレイヤー/監督別の観測DTOと個体の信念をPolicyに渡す。潜在学習率、真の成長限界、他人の非公開状態を含めない。コピー/不変値を使い、PolicyからWorldへの参照を渡さない。
- 判断の契約は `decide(observation, personal_state) -> decision` 程度でよい。Decisionは選んだ行動、候補、実際に使用した得点項/条件、入力となる観測・記憶IDを持つ。モデルがない今回は `policy_version` を記録。
- Aは真の技能・疲労の更新。Bは自己能力の推定、方法別の予想利得、監督の選手評価の更新。Cは未実装と明記。

## 時間と選択

1日は整数の時刻と固定フェーズ。選手は1枠/日、監督は2枠/日を暫定設定。全部の選手を観察・指導するには足りない。係数は設定として記録。

1. 朝: 前日までの結果から私的な自己観測を作る。日予算をリセット。
2. 監督: 観察・練習提案・休息から予算内で選ぶ。観察対象や提案先/方法は自分の推定・不確実性・育成価値によって選択。全選手への固定順の指示列にしない。
3. 選手: 同じ時点の観測を固定し、各自が練習方法A/Bまたは休息を選ぶ。提案が来ていれば採用/拒否をDecisionに記録するが、強制しない。
4. 解決: 時間制約を検証し、選手の行動を解決。反映順で有利不利が出ない。
5. 夕: 自分の練習結果に関する不完全な観測からBを更新。監督は有料の観察で得た情報だけを評価更新に使う。
6. 日終了: 不変条件検査、日次要約、任意のチェックポイント。

観察/提案/休息は各1枠。監督は同一日に同一対象を何度も観察したり同じ提案を繰り返さない。予算超過・不正対象・不正行動は明示的に拒否する。睡眠等の自動背景回復を入れる場合は、休息行動の機会費用を消さない値にし、モデル式に明記する。

## 状態とルールの最低限

- 2人の初期の真の技能は同じ。個別の練習方法への適性、個人の価値重み/方法の好み、自己推定、監督への信頼を保存。
- 潜在学習率は方法A/Bで異なってよい。これをPolicyに直接渡して最適方法を選ばせない。
- Aの候補式: `gain = min(cap-skill, rate[method] * duration * focus * (1-fatigue) * max(0, cap-skill))`。すべて有限で非負、疲労/技能は定義域内。これは検証用のゲーム的モデルで、実際の人体の推定式ではない。
- 予想利得、好み、自律性、信頼、疲労感による得点を比較して決定する。初期Policyは決定論的。IDを性格や行動得点に使わない。
- Bは観測された前後の成績差などから更新する。真のgain・潜在rateを直接読み込まない。監督評価は古いこと・間違っていることが可能。
- 観測ノイズはゼロにできる。監督・本人の情報経路は別々。単純な推定更新でよく、厳密Bayesであると称さない。
- 詳細な係数/Policy式はSolが短い実装ノートに記録する。必要ならT001からの逸脱案を理由とともに親担当へ伝える。

## 乱数・ログ・保存

- 推奨: root seedと `(channel, day, actor_id, draw_index)` から安定したSHA-256でノイズを得るキー付き方式。Pythonの`hash()`を使わない。キーと方式版を保存し、隠れた乱数状態を持たない。別方式なら全stream状態を保存する。
- 不要なログ追加が乱数列をずらさない。介入比較は同じ外生ノイズキーを共有し、条件が異なる行動の結果までは同一と仮定しない。
- Eventは一意ID、day/phase、kind、actor/target、原因イベントID、観測の情報源、Decision、状態更新を持つ。真値を含む研究用ログはPolicyに渡さない。
- 原因リンクは「実際に参照/更新した前段」の追跡であり、因果効果の証明とは呼ばない。
- 小規模なのでJSON snapshotに全履歴を含めてよい（サイズ限界を報告）。JSONLを分析用に出力。再開時は完全履歴を出力し直す形でもよい。
- 保存は一時ファイル+置換。保存形式/ルール/Policy/乱数の版、config、時刻、全永続状態、イベント連番、ソース識別、乱数キー状態を保持。未知の版は黙って読まずエラー。pickleは不要。
- 同一コード・Python環境・設定で、連続28日と14日保存+14日再開のシミュレーション状態・イベント列・正規化hashが一致する。実時間や出力先はシミュレーションhashに含めない。

## CLIの契約

実装時に名前を変更してもREADMEと結果を一致させる。

```text
python3 -m soccer_sim run --seed 17 --days 28 --out artifacts/t001/baseline
python3 -m soccer_sim run --seed 17 --days 14 --out artifacts/t001/first_half
python3 -m soccer_sim resume --snapshot artifacts/t001/first_half/snapshot.json --days 14 --out artifacts/t001/resumed
python3 -m soccer_sim experiment --out artifacts/t001/experiments
python3 -m unittest discover -s tests -v
```

`resume --days` は追加日数。snapshot、events、summary、manifestを出す。experimentは比較の機械可読JSONと簡単な集計を出す。

## 受入条件と比較

1. 全状態が有限・範囲内、日予算超過0、ID/原因参照の不整合0。不正な入力を拒否。
2. 同seedの再実行および保存再開で状態・全イベントが一致。保存版/モデル版不整合を拒否。
3. **隠れた状態の非漏洩**: 今回の観測/信念を固定したまま潜在適性だけを変えても、その時点の判断は同じ。将来は観測を経由して変わってよい。
4. **意味のある学習差**: 同じ初期技能、同じ方法/時間、観測ノイズ0の対照実験で、潜在rateだけ異なると成長差が出る。rateまで同じにすると差が消える。全世界の均質化では監督の資源配分の非対称性が残りうるため、この検査は条件を揃えた独立probeで行う。
5. **選択への影響**: 信頼だけ、または自己の方法別予想利得だけを変えた、判断境界付近の事前定義fixtureで選択が変わる。全ての状態で変わることは要求しない。
6. **経験の影響**: 異なる観測経験の後、同じ次の提示条件で方法の評価/選択が分かれる。B更新停止の対照では経験による更新が消える。初期値だけの差を経験の効果に数えない。
7. **追跡**: ある成長更新から、行動、候補得点、指示/自己観測の入力までIDで辿れる。単なる文章の説明を合格証拠にしない。
8. **比較実験**: 28日×seed 0..29のbaselineと、個人学習率の均質化、B更新停止、ノイズ0を比較。必要なら信頼介入probeも併記。行動割合/指示採用率/技能gain/推定誤差/日数・時間・ログサイズを報告。ノイズ0の差がないなら隠さず失敗/限界として記録。
9. 1000日程度の連続runで状態不整合・例外0を確認し、時間とログ増加を測定。この範囲を越えた長期安定性は未確認。
