# T026 — 年齢の効果: 年度末に技能を成熟・衰えさせる最初の最小形

2026-11-10、実装前登録(結果を見る前に規則を固定)。状態: 完了(2026-11-10、成功条件1〜7を満たし予測P1〜P3は支持)。[結果](../experiments/T026-RESULTS.md)。担当: Claude Sonnet 5.5。着手は継続指示に基づく(T025の提案)。ブランチt026はt025から切る(PR #8の上に積む)。[事前条件](../experiments/T026-PROTOCOL.md)、判断: D041。

## 問題

T025で年齢カウンタができたが、何にも作用しない。引退・新人供給の前に、年齢が技能(真値)へ及ぼす最小の効果が要る。実データによる校正は未着手で、曲線の数値は**未校正の仮説**である。

## 最小の選択と理由

- **曲線形**: 年度末に年齢を+1した直後(到達年齢 a)、全選手の3特性(pace/passing/shooting)へ同じ加算 `delta(a)` を一度だけ加える。`delta(a) = +0.02 (a<=24)`、`0 (25<=a<=29)`、`-0.01*(a-29) (a>=30)`。結果は`clamp(特性+delta, 0.15, その選手のcap)`で`round6`。区分線形の3段(成熟・高原・加速する衰え)で、数値と境界はすべて任意の仮説。選手間・特性間の差、個人の成長率との相互作用は入れない(別task)。
- **フック位置**: 既存の`_age_players`(T025の年度末処理)の中で、`season_aged`の直後に**専用の記録イベント`season_skill_aged`**を1件追加して特性を書き換える。理由: 技能を変える唯一の場所が、年度末に1回、履歴に残る。日々の`_step_training_day`は触らない(日次の成長式に年齢項を混ぜると、年齢の効果と成長の効果が履歴上で分離できない)。`advance_league_days`が進行で行うので、全再演readerは新しい再演経路なしで同じ結果を再現する。
- **有効化**: 設定に任意の文字列`aging_curve`(`"none"`が既定、`"hypothesis_v1"`のみ追加)。`"none"`以外は`aging_start_age>0`が必須。**有効時のみ**configに1キー(既定は出さない=T023/T025と同じ流儀)。`aging_start_age`が有効でも`aging_curve="none"`ならT025と完全に同じ。
- **Policyは真の年齢効果を見ない**: `player_ages`・`aging_curve`を読むのは進行・保存・不変条件のコードだけで、決定関数(`decide_*`)・観測・Policyモジュールは読まない。技能の真値が変わっても、Policyが見るのは従来どおりノイズ付き観測(`obs_skill`等)だけで、年齢は渡さない。年齢のPolicy公開は別task。
- 採らない案: 日次成長式への年齢項(分離不能)、`PlayerTruth.age`(T025で不採用の理由と同じ)、capの低下(上限の意味が変わる)、実データ曲線の採用(出典未選定のため仮説と明記)、年齢別の特性差。

## 互換契約

- 既定(`aging_start_age=0`、`aging_curve="none"`)のconfig・snapshot・events・summary・manifestは不変(T018、T023基準digestと一致)。`aging_start_age>0`かつ`aging_curve="none"`はT025と完全一致。save版17と指紋scopeは不変。`league_economy.py`が指紋対象なのでsource hashは変わる(既存規則)。
- 有効時、`season_skill_aged`が年度末ごとに1件増える(イベントID・直後の台帳イベントの`cause_refs`がずれる。T025補正A1と同じ性質)。
