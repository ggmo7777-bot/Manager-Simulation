# T004: 自己予測Gの切り詰めと信頼を分離する

状態: **実装・検証完了**。2026-11-05、T003結果から候補を作成後、ユーザーの「続けて」により着手。[事前プロトコル](../experiments/T004-PROTOCOL.md)に沿って47テスト・240run・保存再開・旧版との240本照合を完了。[結果](../experiments/T004-RESULTS.md) / [主担当確認](../experiments/T004-REVIEW.md)。最終仕様ではなく、この比較の作業契約である。

## 問題と仮説

T002の真の成長0のprobeでは、観測差を非負に丸めると自己の期待gainが上方に偏った。T003ではこのGを監督予測の比較相手にしている。Gを学ぶかどうかで信頼の変化が逆方向になったが、切り詰め自体の閉ループ効果はまだ調べていない。

候補仮説は「観測差の符号を保つ更新は、非負に丸めた更新とは異なる自己予測・経験・信頼を生む」。技能の伸びや助言の採用を必ず改善するとは予想しない。差が小さくても係数を調整して作り出さない。

## Sol 6.1 Highへの最小作業指示

1. README、CHARTER、STATUS、T002/T003のProtocol・RESULTS・REVIEWを読む。T003までの凍結ソースとartifact一覧のhashを取り、旧結果を保全する。
2. Gの観測標的だけに明示的な方式設定を追加する。既存方式は `max(0, self_after - self_before)`、候補は符号付きの差。EMAの係数、Policy採点、A、ノイズ、信頼式、監督予測、同点規則は維持する。
3. 符号付き方式で本人が負の期待gainを持てるよう、Bの検証・保存・得点入力を確認する。真の技能や潜在率に負の値を許す変更ではない。有限値と合理的な観測範囲を検証し、負値を保存時に黙って0へ戻さない。
4. 旧方式/符号付き × 固定信頼/適応信頼の4条件を比較する。Gそのものは全条件で更新し、他のBもONを維持する。84日、探索0..29・確認100..129。条件・指標・解析seedはProtocolに登録した。
5. 結果と不確実性を記録し、方式を採用するか、対照のまま残すか判断材料を返す。標準設定の変更は結果分析・判断記録の後にする。

## 受入と失敗条件

| 検査 | 受入 | 失敗時の対応 |
|---|---|---|
| 既存基準 | 既存方式でT003と数値/得点/選択が一致 | 他の式が混ざった箇所を切り分ける |
| 更新機構 | 正/負/ゼロの同じ観測列で期待値を検証し、負の信念が保存再開で維持される | 境界・validator・保存を修正 |
| 情報境界 | 同じ私的観測なら潜在率/上限を変えてもG更新が同じ | 真値依存を除く |
| 信頼との順序 | 当日の信頼はG更新前の予測を使い続ける | フェーズ順と根拠IDを修正 |
| 継続 | 4条件で84日vs42+42一致、旧成果物不変、版違いは明示 | 移行を黙って行わず原因を記録 |
| 比較 | 自己予測誤差、負値の頻度、選択/休息、採用機会、信頼、技能gainを別々に報告 | gain改善や不一致率だけで採否を決めない |

行動不一致は比較対象の行動列を直接突き合わせる。同じ条件自身への距離0を引き算して、別条件との差を表したことにしない。統計の実験単位はseedで、固定2プロフィールの範囲を超える一般化はしない。ノイズ0の対照も係数を変えず登録する。

変更候補はG更新の観測標的、Config、必要なBの検証/保存、実験集計。save/rule版とsource hashを明示し、T003は旧bundleで再実行できるよう保つ。既存方式へ設定を戻せるようにする。

同点処理、監督の方法知識の学習、観察の追加費用、複数監督、競技、選考/移籍、Cは今回候補に含めない。次に監督が有料観察から方法知識を更新する経路を検討し、M2から競技/キャリアへ進む。自己予測を完全な心理モデルへ仕上げることは前提にしない。
